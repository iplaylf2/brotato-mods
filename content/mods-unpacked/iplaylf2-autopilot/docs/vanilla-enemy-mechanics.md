# 原版敌人与投射物机制参考

本文是 Autopilot 适配 PC 版 Brotato `1.1.15.4` 时的敌人运动、攻击与投射物机制参考，用于判断
新机制应由哪个观察或编译入口承接，以及升级目标游戏版本时需要重新检查什么。本文不定义玩家
权限或模块边界；权限规则见 [玩家权限边界](fair-play.md)，实现归属见
[模块边界与责任](module-boundaries.md)。

适配目标以 `manifest.json` 为准，本文中的版本号必须与之一致。机制信息以对应版本的本地 GDRETools
恢复工程为准；恢复工程及其原版代码和资源不属于仓库或 mod 发布内容。

## 机制覆盖边界

Autopilot 按以下入口理解敌人运动、攻击和弹道：

- 敌人注册的全部 `ShootingAttackBehavior`，包括普通攻击、附加攻击和 Boss 各阶段攻击；
- 敌人注册的 `ChargingAttackBehavior`，以及 `FollowTargetMovementBehavior` 和
  `StayInRangeFromPlayerMovementBehavior`；
- 敌人注册的 `SpawningAttackBehavior`，以及死亡时直接生成敌人的稳定脚本后果；
- 敌人用于吸附、拾取材料并按累计数量进化的作用区与阈值；
- 敌人节点下常驻的 `EnemyProjectile`；
- 主敌方投射物容器中的移动、静止和动画危险区；
- 不属于任何可移除敌人的环境弹幕；
- 可见敌人与敌方投射物的标准 `Hitbox/Collision` 圆形接触形状。

目标版本的覆盖清单如下：

| 入口 | 目标版本内容 |
| --- | --- |
| 标准或继承的射击行为 | `spitter`、`horned_spitter`、`junkie`、`dire_junkie`、`fly`、`horned_fly`、`lamprey`、`tentacle`、`slasher`、`mad_slasher`、`butcher`、`colossus`、`croc`、`gargoyle`、`invoker`、`mantis`、`mom`、`monk`、`rhino`、`predator` |
| 标准冲撞行为 | `charger`、`horned_charger`，以及复用 `ChargingAttackBehavior` 的阶段或扩展内容 |
| 目标位置响应 | 复用 `FollowTargetMovementBehavior` 或 `StayInRangeFromPlayerMovementBehavior` 的敌人 |
| 材料吸收成长 | `evil_mob`，以及同时公开材料吸附区、拾取区和进化阈值的扩展内容 |
| 存活期间生成 | 复用 `SpawningAttackBehavior` 的蛋、`mom`、`monk` 及扩展内容 |
| 死亡触发生成 | `spawner` 生成 3 个、`bloated_spawner` 生成 5 个子敌人 |
| 敌人子节点常驻投射物 | 腐化树的单枚旋转投射物；`predator` 的九枚旋转投射物 |
| 投射物形态 | 普通移动弹、正弦横摆弹、静止或动画斩击区、柱状区域、附着旋转投射物、环境弹幕 |
| 接触几何 | 敌人与敌方投射物的 `Hitbox/Collision` 均提供标准圆形接触形状；外观尺寸不参与伤害碰撞 |
| 额外击杀收益 | `looter`、增加诅咒且必掉消耗品的 `evil_mob`，以及其他稳定标记为战利品的敌人 |

## Autopilot 处理方式

标准射击行为和敌人子节点中的常驻投射物都有可移除的敌人来源。敌人可见后，
`EnemyMechanicCompiler` 聚合其标准射击与常驻投射物，并委托 `EnemyMotionMechanicCompiler` 编译冲撞和
目标位置响应。两者共同形成射程、弹速、弹量、火力强度、投放模式、静止危险区、死亡清弹规则、
攻击间隔、冲撞可达性、目标响应和最大生命耐久基准。敌人的接触伤害与接触半径也由
`EnemyMechanicCompiler` 编译；当前可见敌方投射物的接触伤害与接触半径由观察器读取。规划层只消费这些
公共字段，不读取场景形状，也不以外观尺寸替代接触几何。
观察器通过 `EntitySpawner.get_all_enemies()` 读取普通敌人与单独存储的 Boss，并把可见敌人的当前生命
作为战斗期测量公开；敌人离开视野后只保留最后一次合法生命观测。最大生命仍属于稳定机制先验，不与
战斗期测量混入同一编译缓存。
`EnemyAttackTimingObserver` 另行形成当前的下一轮齐射与冲撞时间窗：无随机冷却时给出确定时间；有随机
冷却时只给出稳定范围，不读取尚未通过表现揭示的本轮随机结果。

目标位置响应保留两类原版距离语义：启用近距停止的 `FollowTargetMovementBehavior` 进入偏好距离后停住，
`StayInRangeFromPlayerMovementBehavior` 则在距离过近时向外恢复距离。规划器按该差异预测敌人路径，不把
两者合并为同一种远离响应。

冲撞画像还区分任意地图点、玩家位置和玩家周边随机点。规划器只对瞄准玩家区域的冲撞构造高速扫掠走廊，
并把玩家周边随机点的最大偏移作为走廊宽度；闪避方向由候选路径与该走廊的交会关系产生。具有材料吸附区、
拾取区和进化阈值的敌人则形成 `material_assimilation` 画像。规划层按当前可见材料的竞速几何估计材料损失与
敌人成长负担，不为 `evil_mob` 或任何敌人类别设置固定击杀优先级。

存活期间生成按稳定生成率和剩余时间增加来源的移除价值；机制带有最大次数时，同时以生命周期生成上限封顶。
`spawner` 与 `bloated_spawner` 并不在存活期间持续生产，而是在死亡时生成子敌人；该生成量作为移除后果
抵扣当前击杀价值。两类机制因而从相反的实际战场后果进入同一账本，不共享“生成者优先级”。

腐化树和 `predator` 的旋转投射物不在主敌方投射物容器中，因此观察器还会遍历可见敌人的子节点。
环境弹幕没有可移除的敌人来源，只作为具体可见弹道参与规避，不会产生敌人移除机会。

`Projectile` 把 `sinusoidal_motion` 作为随相位变化的速度偏移直接叠加到基础速度；某一时刻从位置差测得的
加速度可能接近零，但这不代表随后仍沿当前切线运动。投射物形成后，当前相位、速度振幅和角频率已唯一
决定后续曲线；`ProjectileMotionCompiler` 公开这些解析参数，规划器直接积分原版速度方程。发射前尚未
决定的随机方向、散布和速度仍只表示为区间；弹体出现后，其结果已经包含在可见基础速度中。

敌人的基础材料、基础消耗品概率、消耗品成为箱子的条件概率、必掉约束和击杀造成的玩家属性变化同样在
可见后编译为 `kill_rewards`。规划层只在稳定消耗品概率内应用箱子条件概率，并以当前幸运换算当轮概率；
`evil_mob` 的击杀结果还包含诅咒 `+1`。目标最后观测剩余生命、武器输出和剩余时间共同决定击杀收益的
可兑现程度；没有合法生命测量时才退回稳定最大生命先验。
目标版本的诅咒概率曲线为 `limit × (1 - 1 / (1 + curse / 50))`：诅咒敌人概率上限为 `0.5`，
诅咒商品概率上限读取当前 DLC 的 `max_curse_item_chance`。属性机会画像保留这些版本参数，规划层使用
当前诅咒下的边际概率，并按普通模式剩余波次折算；无尽模式不作终局折算。击杀收益按剩余时间内的
可击杀性折算。

对于没有使用标准攻击入口的扩展内容，观察器仍可根据可见发射行为形成观察归因；该证据不会覆盖已经
编译的稳定机制知识，也不补造投射物的碰撞几何。新入口若既不能由编译器处理，也不会经过可见投射物
观察，就属于未覆盖机制；敌人或敌方投射物若未公开标准圆形接触形状，也属于未覆盖内容。声明覆盖该
内容或支持新游戏版本前，必须先补齐对应入口。

## 维护规则

- 目标 Brotato 版本不变但适配实现新增或修改时，同步更新“机制覆盖边界”和“Autopilot 处理方式”。
- 目标 Brotato 版本变更时，以新版本恢复工程重新执行下方清单，再更新本文的版本号、覆盖内容和实现映射。
- 内容以维护当前实现所需的稳定机制、入口和覆盖结论为限；调查过程不属于本参考的维护范围。
- 不得将恢复工程、原版脚本或资源复制进 mod 包或仓库内容。

## 版本升级检查清单

升级目标游戏版本时，应重新检查：

1. 所有引用或继承标准射击与冲撞行为脚本的敌人场景；
2. 跟随目标和与玩家保持距离的移动行为字段及其挂载位置；
3. Boss 状态是否继续通过 `_all_attack_behaviors` 注册；
4. 敌人场景中是否新增常驻 `EnemyProjectile` 子节点；
5. `SpawningAttackBehavior` 的生成率、次数上限，以及绕开该入口的死亡生成脚本是否变化；
6. 投射物容器、运动字段、曲线弹道解析参数、攻击随机边界和死亡时清除投射物的规则是否发生变化；
7. 敌人与敌方投射物是否继续通过标准 `Hitbox/Collision` 公开圆形接触形状；
8. 冲撞目标类型、玩家周边随机点范围、材料吸附/拾取作用区和进化阈值是否变化；
9. 战利品敌人的基础材料、基础消耗品概率、箱子条件概率、必掉约束和诅咒收益是否变化；
10. “机制覆盖边界”中的敌人清单和投射物形态是否仍然完整；
11. 目标版本声明、恢复工程的游戏版本和本文的版本号是否一致。

若入口发生变化，先更新机制编译或观察边界，并在目标环境完成验证，再修改目标版本声明。
