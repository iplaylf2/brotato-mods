# 原版敌人、树木与投射物机制参考

本文是 Autopilot 适配 PC 版 Brotato `1.1.15.4` 时的敌人阵营、运动、攻击与死亡奖励、树木完成条件及投射物
机制参考，用于判断新机制应由哪个观察或编译入口承接，以及升级目标游戏版本时需要重新检查什么。
本文不定义玩家权限或模块边界；权限规则见 [玩家权限边界](fair-play.md)，实现归属见
[模块边界与责任](module-boundaries.md)。

适配目标以 `manifest.json` 为准，本文中的版本号必须与之一致。基础游戏机制以对应版本的本地 GDRETools
恢复工程为准；恢复工程及其原版代码和资源不属于仓库或 mod 发布内容。恢复工程未包含的 DLC 脚本不能
仅凭类注册路径或基础项目代码推断其行为；此类映射在取得同版本 DLC 资源或目标环境证据前，列入
[仍需校准的假设](model-calibration.md#仍需校准的假设)，不作为本文的已确认覆盖结论。

## 机制覆盖边界

Autopilot 按以下入口理解敌人阵营与运动、攻击、树木完成条件和弹道：

- 敌人注册的全部 `ShootingAttackBehavior`，包括普通攻击、附加攻击和 Boss 各阶段攻击；
- 敌人注册的 `ChargingAttackBehavior`，以及 `FollowTargetMovementBehavior` 和
  `StayInRangeFromPlayerMovementBehavior`；
- 敌人注册的 `SpawningAttackBehavior`，以及死亡时直接生成敌人的稳定脚本后果；
- 敌人用于吸附、拾取材料并按累计数量进化的作用区与阈值；
- 敌人的材料数量、消耗品条件、必掉产物、可见效果施加的材料倍率和机制明确的死亡属性变化；
- 敌人节点下常驻的 `EnemyProjectile`；
- 主敌方投射物容器中的移动、静止和动画危险区；
- 不属于任何可移除敌人的环境弹幕；
- 可见敌人与敌方投射物的标准 `Hitbox/Collision` 接触形状，包括动画位移的矩形斩击区；
- `Boss` 基类在 `hp_bar_on_bosses` 启用时公开的持续生命条，包括 `is_elite` 为真或假的实例；
- `EntitySpawner.get_all_enemies(include_charmed_enemies)` 对完整敌人集合与当前敌对目标域的划分，以及
  `Enemy.get_charmed_by_player_index()` 公开的转化归属；
- 树木的生命扣减、命中计数终止条件，以及玩家的一击树效果。

当前实现按下列入口声明覆盖。涉及恢复工程未包含的 DLC 内容时，该清单描述适配范围，不替代目标环境
回归证据：

| 入口 | 当前适配范围 |
| --- | --- |
| 标准或继承的射击行为 | `spitter`、`horned_spitter`、`junkie`、`dire_junkie`、`fly`、`horned_fly`、`lamprey`、`tentacle`、`slasher`、`mad_slasher`、`butcher`、`colossus`、`croc`、`gargoyle`、`invoker`、`mantis`、`mom`、`monk`、`rhino`、`predator` |
| 标准冲撞行为 | `charger`、`horned_charger`，以及复用 `ChargingAttackBehavior` 的阶段或扩展内容 |
| 目标位置响应 | 复用 `FollowTargetMovementBehavior` 或 `StayInRangeFromPlayerMovementBehavior` 的敌人 |
| 材料吸收成长 | `evil_mob`，以及公开相同材料吸附、拾取和成长交互的扩展内容 |
| 存活期间生成 | 复用 `SpawningAttackBehavior` 的蛋、`mom`、`monk` 及扩展内容 |
| 死亡触发生成 | `spawner` 生成 3 个、`bloated_spawner` 生成 5 个子敌人 |
| 敌人子节点常驻投射物 | 腐化树的单枚旋转投射物；`predator` 的九枚旋转投射物 |
| 投射物形态 | 普通移动弹、正弦横摆弹、静止或动画斩击区、柱状区域、附着旋转投射物、环境弹幕 |
| 接触几何 | 敌人提供圆形 `Hitbox/Collision`；普通弹体使用圆形，斩击区使用随动画改变位置和范围的矩形；外观尺寸不参与伤害碰撞 |
| 持续生命条 | `Boss` 基类承载精英与 Boss 的生命条；`hp_bar_on_bosses` 决定是否向玩家持续公开 |
| 敌人与转化单位 | `get_all_enemies(true)` 包含转化单位，`get_all_enemies(false)` 给出原版自动攻击使用的当前敌对域；转化归属由 `get_charmed_by_player_index()` 给出 |
| 额外死亡奖励 | 被诅咒敌人的材料倍率、`looter` 的箱子，以及其他可见机制决定的稳定奖励或死亡属性变化 |
| 树木完成条件 | 生命归零、伤害事件计数达到默认上限 8，或 `one_shot_trees` 在合法玩家命中时直接完成 |

## Autopilot 处理方式

### 敌人与投射物

标准射击行为和敌人子节点中的常驻投射物都有可移除的敌人来源。敌人可见后，
`EnemyMechanicCompiler` 聚合其标准射击与常驻投射物，并委托 `EnemyMotionMechanicCompiler` 编译冲撞和
目标位置响应。两者共同形成射程、弹速、弹量、火力强度、投放模式、静止危险区、死亡清弹规则、
攻击间隔、冲撞可达性、目标响应和最大生命耐久基准。敌人的接触伤害与接触半径也由
`EnemyMechanicCompiler` 编译。对于当前可见的敌方投射物，观察器读取实际 `Hitbox` 中心、接触伤害及
包围完整碰撞形状的半径。规划层只消费这些公共字段，不读取场景形状，也不以外观尺寸替代接触几何。
原版 `slash_projectile.tscn` 与 `slash_projectile_2.tscn` 的 `RectangleShape2D` 会在攻击动画中同时改变位置与
`extents`，因此弹体节点锚点和圆形专用 `radius` 都不能表达其伤害区域。
观察器比较 `EntitySpawner.get_all_enemies(true)` 的完整集合与 `get_all_enemies(false)` 的当前敌对域。
仍为敌对的普通敌人、精英与 Boss 进入敌人观察；差集中的转化单位进入友方观察，并以
`get_charmed_by_player_index()` 标明归属。敌人转化时，同源节点证据立即终止其旧敌对轨迹，不等待失视
记忆过期。转化单位不再贡献敌对压力、碰撞伤害或完成价值；其友方攻击能力尚未形成通用画像，因此当前
只保留可见运动和身体几何。

观察器把可见敌人的当前生命作为战斗期测量公开。普通敌人离开视野后只保留最后一次合法生命观测；原版
持续血条目标则继续公开当前生命与存活，但不更新视觉位置。最大生命仍属于稳定机制先验，不与战斗期
测量混入同一编译缓存。
`EnemyAttackTimingObserver` 另行形成当前的下一轮齐射与冲撞时间窗：无随机冷却时给出确定时间；有随机
冷却时只给出稳定范围，不读取尚未通过表现揭示的本轮随机结果。

目标位置响应保留两类原版距离语义：启用近距停止的 `FollowTargetMovementBehavior` 进入偏好距离后停住，
`StayInRangeFromPlayerMovementBehavior` 则在距离过近时向外恢复距离。规划器按该差异预测敌人路径，不把
两者合并为同一种远离响应。

冲撞画像区分任意地图点、玩家位置和玩家周边随机点。任意地图点不形成针对玩家的冲撞风险；直接瞄准
玩家与玩家周边随机点则分别编译为目标权重、前向越过距离和随机偏移范围。规划器在随机结果揭示前用
固定五点矩匹配求积近似交会风险，并在每个求积点按候选玩家运动解析计算 TTC；冲撞形成可见高速运动后，
改用已经实现的观测路径。候选间的风险差异由目标分布、相对运动和到达时间产生，不指定闪避方向。

具有材料吸附区、拾取区和进化阈值的敌人形成 `material_assimilation` 画像。规划层按当前可见材料的竞速
几何估计材料损失与敌人成长负担，不为 `evil_mob` 或任何敌人类别设置固定击杀优先级。

存活期间生成按稳定生成率和剩余时间增加来源的存活负担解除价值；机制带有最大次数时，同时以生命周期
生成上限封顶。
`spawner` 与 `bloated_spawner` 并不在存活期间持续生产，而是在死亡时生成子敌人；该生成量作为移除后果
进入死亡后果成本。两类机制因而从相反的实际战场后果进入同一账本，不共享“生成者优先级”。

腐化树和 `predator` 的旋转投射物不在主敌方投射物容器中，因此观察器还会遍历可见敌人的子节点。
环境弹幕没有可完成的敌人来源，只作为具体可见弹道参与规避，不会产生敌人完成价值。

`Projectile` 把 `sinusoidal_motion` 作为随相位变化的速度偏移直接叠加到基础速度；某一时刻从位置差测得的
加速度可能接近零，但这不代表随后仍沿当前切线运动。投射物形成后，当前相位、速度振幅和角频率已唯一
决定后续曲线；`ProjectileMotionCompiler` 公开这些解析参数，规划器直接积分原版速度方程。发射前尚未
决定的随机方向、散布和速度仍只表示为区间；弹体出现后，其结果已经包含在可见基础速度中。

### 树木

原版 `Neutral.take_damage()` 先执行 `Unit.take_damage()` 的生命扣减与生命归零死亡，再累计
`current_number_of_hits`。计数达到默认上限 8 时，只要该伤害事件没有被非玩家 hitbox 的来源检查排除，
树木也会强制死亡；`one_shot_trees` 则只在合法玩家命中时直接完成树木。因此生命归零和命中计数是两条
并行完成路径。Autopilot 同时观察树木生命和计数进度，并把该玩家效果适配为“一次玩家命中即完成中立
实体”的能力。

### 敌人死亡奖励与诅咒机会

敌人的当前材料数量、可见机制施加的材料倍率、基础消耗品概率、消耗品成为箱子的条件概率和必掉约束
同样在可见后编译为 `death_rewards`。被诅咒敌人的额外材料因而进入通用结算语义，不需要身份优先级。
原版 `Main.spawn_loot()` 将 `Unit.get_stats_value()` 的返回值直接交给材料结算：基类返回 `stats.value`，
`evil_mob` 返回当前吸收材料数乘以 `阶段 + 1`。目标版本这两个实现都由当前机制状态和确定性规则决定，
因此 Autopilot 使用其当前精确数量，再组合单位效果提供的材料倍率。是否实际掉落仍由独立概率模型处理。

规划层按当前波次和潮汐波规则计算材料掉落概率。任意消耗品概率由基础概率与当前幸运估计，箱子条件
概率再独立结合幸运并与前者相乘。当前模型没有读取本波已生成箱子数，因此不包含原版
`_items_spawned_this_wave` 对后续箱率的衰减；也尚未组合玩家箱率修正和无尽模式的消耗品衰减。这些结果
是规划代理，不应在复盘中当作完整原版概率。具备必掉产物的目标同时公开产物类型和原版最大生成位移，
供观察层在机制支持域内已追踪来源唯一时，把首次看到的宝箱等产物关联回失视目标；来源不唯一时不作
身份推断。目标当前合法感知的剩余生命、武器输出和剩余时间共同决定死亡奖励的可兑现程度；持续血条
目标在视野外仍更新生命，没有合法生命测量时才退回稳定最大生命先验。
`looter` 的较高结算材料、必掉消耗品、箱子概率、较低耐久和观测运动与其他敌人进入同一可交战目标
账本；当这些机制使其净完成价值和可达性胜出时，优先追击自然出现。

目标版本的诅咒概率曲线为 `limit × (1 - 1 / (1 + curse / 50))`：被诅咒敌人概率上限为 `0.5`，
诅咒商品概率上限读取当前 DLC 的 `max_curse_item_chance`。属性机会画像保留这些版本参数，规划层使用
当前诅咒下的边际概率，并按普通模式剩余波次折算；无尽模式不作终局折算。敌人死亡奖励按剩余时间内的
可击杀性折算。

### 扩展内容覆盖

对于没有使用标准攻击入口的扩展内容，观察器仍可根据可见发射行为形成观察归因；该证据不会覆盖已经
编译的稳定机制知识，也不补造投射物的碰撞几何。新入口若既不能由编译器处理，也不会经过可见投射物
观察，就属于未覆盖机制。敌人或敌方投射物的标准 `Hitbox/Collision` 节点若未使用当前支持的
`CircleShape2D` 或 `RectangleShape2D`，也属于未覆盖内容。声明覆盖该内容或支持新游戏版本前，必须先
补齐对应入口。

## 维护规则

- 目标 Brotato 版本不变但适配实现新增或修改时，同步更新“机制覆盖边界”和“Autopilot 处理方式”。
- 目标 Brotato 版本变更时，以新版本恢复工程重新执行下方清单，再更新本文的版本号、覆盖内容和实现映射。
- 内容以维护当前实现所需的稳定机制、入口和覆盖结论为限；调查过程不属于本参考的维护范围。
- 恢复工程缺少对应脚本的 DLC 规则只记录适配范围；确认前应在模型校准文档中保留证据缺口与复核方法。
- 不得将恢复工程、原版脚本或资源复制进 mod 包或仓库内容。

## 版本升级检查清单

升级目标游戏版本时，应重新检查：

1. 所有引用或继承标准射击与冲撞行为脚本的敌人场景；
2. 跟随目标和与玩家保持距离的移动行为字段及其挂载位置；
3. Boss 状态是否继续通过 `_all_attack_behaviors` 注册；
4. 敌人场景中是否新增常驻 `EnemyProjectile` 子节点；
5. `SpawningAttackBehavior` 的生成率、次数上限，以及绕开该入口的死亡生成脚本是否变化；
6. 投射物容器、运动字段、曲线弹道解析参数、攻击随机边界和死亡时清除投射物的规则是否发生变化；
7. 敌人与敌方投射物是否继续通过标准 `Hitbox/Collision` 公开接触形状，以及是否新增非圆形或动画形状；
8. 冲撞目标类型、玩家周边随机点范围、材料吸附/拾取作用区和进化阈值是否变化；
9. `get_stats_value()` 及其覆盖、可见机制材料倍率、基础消耗品概率、箱子条件概率、本波箱子衰减、
   玩家箱率修正、无尽模式衰减、必掉约束和死亡属性变化是否变化；
10. 树木的基础生命成长、命中上限、伤害事件计数入口与 `one_shot_trees` 效果是否变化；
11. “机制覆盖边界”中的敌人清单和投射物形态是否仍然完整；
12. 精英与 Boss 是否仍共用 `Boss` 基类，以及 `hp_bar_on_bosses` 是否仍控制持续生命条；
13. `get_all_enemies()` 的转化单位包含参数、自动攻击敌对域和转化归属入口是否变化；
14. 目标版本声明、恢复工程的游戏版本和本文的版本号是否一致；恢复工程缺少的 DLC 脚本是否另有同版本
    资源或目标环境证据。

若入口发生变化，先更新机制编译或观察边界，并在目标环境完成验证，再修改目标版本声明。
