# 原版玩家效果与武器机制审计

本文记录 Brotato `1.1.15.4` 中会改变战斗移动决策的玩家效果与武器机制，以及它们在 Autopilot 公共
模型中的覆盖状态。它是版本复核清单，不是角色、道具或武器图鉴；普通属性变化已经反映在玩家和武器的
实时有效数值中，因此不按内容名称重复登记。本文不定义权限或公共模型；权限规则见
[玩家权限边界](fair-play.md)，模型语义与扩展条件见 [架构文档](architecture.md)。

## 审计范围与方法

本审计覆盖恢复工程中 `items/all` 的 208 个内容目录，以及 `weapons/melee` 和 `weapons/ranged` 的
63 个武器族、206 条带 `weapon_` 内容 ID 的武器数据定义。检查同时追踪了道具 `Effect` 的存储方式、
玩家效果聚合表、武器各阶属性、武器效果资源，以及玩家、单位、投射物和主场景中的实际触发代码。
角色效果尚未完成与道具同等范围的全量枚举；当前只记录排查中已经沿聚合键、角色资源和运行时消费者
闭环确认的机制，不能把本表解释为完整角色覆盖清单。

判断标准不是效果是否稀有，而是它是否改变以下任一问题：是否移动、移动到哪里、何时进入射程、何时
拾取、是否承受一次攻击，以及某次自动攻击的空间收益。商店价格、重掷、升级和纯波间经济等不会改变
战斗中的移动动作，只需由原版系统结算；敌人数、速度和生命等生成配置则通过实际可见实体进入观察，
不在规划层复制。

## 审计结论与当前建模边界

下表区分原版机制事实与规划层的当前处理方式。列入审计不等于逐发模拟，也不单独证明游戏内行为或数值
已经校准；整体验证状态以 [Autopilot README](../README.md) 为准。

| 机制族 | 代表内容 | 当前语义 |
| --- | --- | --- |
| 移动/静止条件属性与禁止移动攻击 | Barricade、Chameleon、Statue、Soldier | 候选动作投影有效属性和攻击许可，并为持续站立或移动计时 |
| 材料与消耗品事件 | Metal Detector、Cute Monkey、Baby Elephant、Extra Stomach、Spicy Sauce，以及 Chef 的燃烧消耗品爆炸 | 按候选路径进入收集半径的时刻预测材料、恢复、成长、范围伤害、持续状态及状态窗口内的后续伤害增量 |
| 材料立即装填 | 相应玩家/武器效果 | 武器结果预测读取当前可感知冷却；规则适配层保留“拾取时重置冷却”的版本语义，但尚未把拾取事件传播到同一预测窗内的武器时序，因此暂不计这次逐发协同 |
| 受击、闪避与恢复事件 | Riposte、Adrenaline、Triangle of Power、Bull | 以预计命中/闪避概率预测反击、恢复、临时属性和爆炸收益 |
| 特殊治疗约束 | Torture、禁止治疗效果 | Torture 屏蔽普通治疗价值但保留固定每秒恢复；禁止治疗不会追逐无效果实或治疗区 |
| 波末保留目标 | Pacifist、Cryptid 类规则 | 敌人和树在接近波末时可获得保留价值，不用内容专属模式切换 |
| 可见宠物与构筑物 | 炮塔、地雷、花园、Wandering Bot、Jellyshield 等 | 出现后按可见作用区建模战斗、治疗、减速、拦截和资源作用 |
| 暴击击杀奖励 | Hunting Trophy、Tentacle | 以伤害占敌人最后观测剩余生命的击杀进度预测材料与恢复；缺失合法生命测量时退回最大生命先验 |
| 弹匣式节奏 | Revolver、Chain Gun | 当前可感知的剩余冷却与已显现攻击相位共同确定下一次就绪时间；后续额外长装填折入长期期望攻击间隔，不读取尚未揭示的下一次随机冷却，不设置规划侧最小攻击周期，也不安排具体攻击 |
| 交替近战形态 | Fighting Stick、Sword、Vorpal Sword、Excalibur | 玩家自身可感知的下一击形态进入投送画像；结果预测只估计该形态的连续覆盖，不模拟挥击轨迹 |
| 自动目标与路径碰撞 | `Weapon.Range` 的敌人和中立单位碰撞层；`Weapon.should_shoot()` 的中心距离射程判断 | 可见敌人与树共同形成统一目标集合；编译器把原版 `max_range + 50` 写入精确中心锁定边界，并把 `max_range` 保留为主路径最大传播距离。锁定只决定能否开始攻击；外观半径只参与路径交会。结果预测按最近目标次序确定主目标，再以共享路径接触份额约束局部命中、伤害、完成价值和命中后规则；导航仅按锁定边界计算截止射程访问，不使用路径接触份额。规划器不指定目标，也不求解逐发碰撞顺序 |
| 穿透、弹射与暴击链 | Bandana、Ricochet、Crossbow、Shuriken | 穿透按攻击走廊内的覆盖质量估计，弹射按可重定向覆盖质量估计；两者均受投送容量和逐阶段伤害保留率约束，不构造有序路径 |
| 命中后二次武器效果 | 爆炸武器、燃烧武器、Cactus Mace、Lightning Shiv、Sniper Gun、Vorpal Sword | 把锚点、目标选择、覆盖半径、容量和伤害缩放压缩为命中后的期望投送，不传播具体事件链 |
| 动态武器数值 | Stick、Rail Gun、Ghost 武器及属性换算内容 | 直接读取 `current_stats`；已经生效的堆叠、无伤成长、套装和属性换算无需识别内容 ID |

上表只是版本审计索引，不是决策模型。规划器不会接收这些内容或机制类别；所有武器统一压缩为
`timing`、`delivery`、`impact` 三个状态轴及 `rules` 状态转移语言，玩家效果也统一压缩为事件、条件和
状态变换。新增内容只有在这组轴无法表达一个会改变移动选择的事实时，才允许扩展公共模型。
在实现代码中，目标版本的原版字段、内容名称和原版资源类型只允许出现在 `bot/knowledge` 版本知识边界；
本文作为版本审计索引保留对应名称，规划契约不依赖这份清单。

Chef 的角色资源声明消耗品拾取触发燃烧爆炸，并提高对燃烧目标的非元素伤害；主场景在正常拾取消耗品时
调用普通与燃烧两类爆炸效果。版本知识层分别把它们编译为 `consumable_pickup` 的空间伤害/燃烧状态后果，
以及以燃烧状态为条件的 `damage_dealt` 倍率。规划层只消费这些规范规则，不读取 `character_chef`；角色
ID 仅随诊断样本记录，用于发现角色正确但规则缺失的适配问题。

武器结果预测的语义、采样结构和容量上限见架构文档的
[“武器结果预测”](architecture.md#武器结果预测)。公共攻击模型的扩展决策由
[“攻击模型的当前边界与扩展条件”](architecture.md#攻击模型的当前边界与扩展条件)统一维护；本审计只记录
目标版本的机制覆盖，不另设按内容名称展开的设计待办。

## 版本升级复核

升级目标游戏版本时，应重新执行以下检查：

1. 枚举 `items/all`、角色资源和两类武器目录，比较新增、删除和改名的内容族。
2. 汇总所有效果资源的脚本类型、`key`、`custom_key` 与 `storage_method`，确认新增字段有明确的运行时消费者。
3. 比较 `WeaponStats`、`RangedWeaponStats`、`MeleeWeaponStats` 和 `Weapon` 的时序、形态、目标碰撞层、
   `should_shoot()` 中的中心距离准入量及命中处理字段。
4. 搜索玩家效果聚合表中的新增键，并追踪玩家、单位、投射物、主场景和构筑物的读取位置。
5. 对每个新增机制判断其是否改变波内移动；若改变，优先扩展共享语义轴，再在 `bot/knowledge` 添加版本映射。
6. 完成源码编译检查，并在游戏内分别验证站立限制、材料装填、Torture、闪避触发、消耗品燃烧爆炸及其
   状态协同、长期弹匣节奏、交替近战覆盖、敌人与树的目标覆盖、弹射容量、爆炸/燃烧/派生投射物的期望
   投送和斩杀武器。
