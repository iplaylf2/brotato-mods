## 运行链路

```text
RunData 扩展
└── 整局采样 ID：生成、存档与恢复

主场景扩展
├── ObservationService
│   ├── 当前观察：PlayerStateObserver、VisibleWorldObserver
│   ├── 版本知识：bot/knowledge
│   └── 局内记忆：ObservedWorldMemory
├── AutopilotController（仅在控制开启时存在）
│   ├── PhysicsFrameBudgetMonitor
│   ├── PlanningWorker
│   │   └── MovementPlanner
│   │       ├── 投射物可达性过滤、计算预算与导航意图
│   │       ├── 动作生成与结果预测
│   │       └── 效用评价与动作选择
│   └── AutopilotMovementBehavior
└── BattleSampleRecorder（仅在采样开启时存在）
    └── BattleSampleWriter
```

`RunData` 扩展拥有整局采样 ID：新对局重置时生成，保存和恢复对局状态时一并存取。主场景扩展作为组合根，
按设置管理观察服务、控制器和样本记录器的波次生命周期；控制或采样至少一项开启时才创建观察服务。

启用 Autopilot 后，控制器定期读取观察并请求运动计划，只把计划中的首个移动方向交给
`MovementBehavior`；这是系统唯一的控制边界。重规划起点按六个
物理 tick 的绝对节拍推进，后台计算占用这个周期而不会被额外加在周期之后；若计算跨过下一个起点，
控制器从结果提交时的物理帧建立新周期，不追赶过时的积压请求。波次清场时，主场景扩展先停止控制器并
恢复原移动行为，再关闭样本记录器，最后由原版释放战斗节点。游戏暂停时，观察、规划和采样一并停止。速度、
碰撞、击退、动画、瞄准、攻击触发和移动机制均由原版 `Player`、`Unit` 与武器系统负责。

观察层每个物理帧更新可见世界、运动估计、里程计和记忆，但只在读取时物化观察快照；这样持续感知仍为
原物理频率，而随局内记忆增长的轨迹与实体副本只按重规划频率构造一次。公共读取保留防御性深拷贝；
`ObservationService` 另行截取与观察状态隔离的规划值快照，其中只含已经脱离场景节点的嵌套值，不携带
规划不消费的机制证据副本。控制器把快照和帧预算上下文提交给 `PlanningWorker`；工作线程内部创建并独占
每位玩家的规划器，在同一线程配置、执行和释放其可变模型状态，然后只返回值结果，控制器在主线程整体
替换计划。`PlanningWorker` 独占 Godot 3 的长期线程、信号量、互斥交接和退出协议，不读取或回调活动
场景树。工作线程无法启动时，控制器不安装动作适配器；运行中拒绝请求时，控制器停止 Autopilot 并恢复
原移动行为。两种情况都不会在物理线程降级执行规划。

`BattleSampleRecorder` 独立于控制器存在。human 分段由它按固定间隔读取公共观察中的实际移动输入；bot
分段由控制器把已经取得的观察和只读规划账本提交给它。运行中若规划工作线程拒绝新请求，记录器会先关闭
bot 分段，再转入 human 分段。记录器负责采样准入、控制来源和波次分段生命周期；
`BattleSampleWriter` 只负责在独占写入线程中压缩观察、编码 JSON Lines、刷新和落盘。分段元数据和波次
上下文各记录一次，每位玩家的固定上下文也只在其首次样本前记录。写入失败只会停止当前分段接受记录，
不改变移动控制；正常关闭会等待队列排空并写入分段结尾。性能验证方法见
[性能与计算预算](model-calibration.md#性能与计算预算)。

`PhysicsFrameBudgetMonitor` 读取 Godot 报告窗口内的物理回调峰值，在同一 `idle frame` 内只推进一次
平滑估计。引擎计时止于该边界；动作决策和计算预算准入分别归属 `MovementPlanner` 与
`PlanningComputeBudgetPolicy`。

代码依赖保持单向：主场景扩展依赖 `control`、`sampling` 与 `observation`；`control` 依赖 `observation`
与 `planning`，`sampling` 依赖 `observation`，`observation` 依赖 `knowledge`。规划层只接收已经移除场景
节点的观察字典；
`bot/observation/observation_service.gd` 是观察的公共读取入口。完整入口与跨包契约见
[模块边界与责任](module-boundaries.md#运行时边界与依赖)。

## 观察契约

### 公共入口与顶层结构

控制或采样至少一项开启且玩家生成后，可以从主场景读取某位玩家的最新观察：

```gdscript
var observation: Dictionary = main.autopilot_observation_service.get_observation(player_index)
```

观察由九个顶层部分组成：

```text
physics_frame
wave_state
player_state
├── dead
├── health
├── progression
├── resources
├── inventory
├── effective_stats
├── stat_opportunity_profiles
├── runtime_stats
├── collision_radius
├── movement
├── pickup
├── weapons
└── effect_rules
party_state
localization
enemy_tracks
remembered_entities
visibility
visible_world
```

`visible_world` 只包含当前可见的树木、友方角色、构筑物、材料、消耗品、敌方投射物和生成警告。
`spawn_warnings` 中每条记录公开以下字段：

| 字段 | 含义 |
| --- | --- |
| `kind` | 固定为 `spawn_warning` |
| `relative_position` | 警告中心相对当前玩家的位置 |
| `disposition` | 从警告颜色可辨认的 `hostile`、`neutral` 或 `allied` |
| `interaction_radius` | 警告区自身的稳定碰撞半径；规划层另行叠加玩家碰撞半径 |
| `resolution_window` | 警告结束前的时间；结构沿用通用时间窗契约，当前两端相等且 `is_exact` 为真 |
| `player_overlap_defers_spawn` | 玩家在警告结束时重叠该区域，是否会使敌人换位并重新开始警告 |

观察层直接读取驱动可见加速闪烁的当前倒计时，并换算成精确 `resolution_window`。敌对警告因玩家重叠而
换位并重新开始时，原版倒计时随可见相位一起重置，观察层无需维护并行的首次观测计时器。该字段的权限
依据见 [玩家权限边界](fair-play.md#判定原则)。

可见材料的 `material_quantity` 直接取原版拾取和波末转换所消费的当前 `Gold.value`。该结算值在材料形成后
已经确定，不包含未来随机结果；它随实体一起进入记忆，使已见材料离开视野后仍保留相同数量。
`wave_state` 包含当前波次、最终波次、无尽模式与潮汐波标记、剩余秒数和波次时长。
`player_state.runtime_stats.minimum_invincibility_seconds` 由原版 `Player.get_iframes(0)` 在观察时给出，因而
包含当前无尽波次缩放；规划层不复制这条版本规则。
`player_state.stat_opportunity_profiles` 按规范属性名提供未来事件概率曲线。每条画像包含 `curve`、
`scale` 和 `chance_limits`；这些目标版本参数由属性知识模块适配，规划层据此计算属性变化的边际机会。
敌人统一由 `enemy_tracks` 表示：可见时更新测量值，离开视野后根据最后一次速度与衰减加速度
估计位置，并附带距上次出现的时间、置信度和不确定范围。`visual_radius` 通常从精灵尺寸估算，只用于
可见性、邻近压力和命中路径交会等外观尺度职责。伤害碰撞改用 `contact_radius`：观察层将标准圆形或矩形
`CollisionShape2D` 转换成以实体记录位置为中心、包围实际命中形状的半径。`visual_radius` 不得替代该
碰撞契约；未通过标准碰撞节点公开受支持形状的扩展内容不属于当前支持范围，必须先扩展机制入口。

### 实体记忆与存在信念

`remembered_entities` 永久保存本局中已经合法看见过的材料、消耗品、树和构筑物。实体持续可见时，
同一条记录会刷新位置、运动状态和最后可见时间；离开视野后才保留最后观测并估计当前存在性。记录证明
观察确实发生过；`existence_confidence` 表示实体现在仍存在的可信程度。时间本身不构成消失证据，
置信度下降也不会删除记录。

材料或消耗品没有再次出现，且玩家或可见队友的实际拾取圆覆盖其记忆位置时，记忆层可以确认它已消失；
实体只进入吸附范围时，则按实际距离累计消失风险。队友离开视野后，系统仅以最后一次合法位置、速度、
实际移动速度和拾取半径估计可达区域。不曾定位过的队友不会产生风险；没有存活队友且玩家自身也未进入
拾取过程时，离开视野的材料和消耗品不会自行降低存在置信度。无雾波次中，合法视口重新覆盖静止树木的
最后观测位置且没有再次看到它时，可以确认该树已消失；敌人消失后则先以最后速度、稳定移动速度及冲撞
速度的最大值形成可达圆，只有整个可达圆仍被合法视口覆盖时才确认其不存在。这样已经击杀的近距离敌人
不会在固定记忆期内继续参与完成价值竞争，靠近视口边缘后可能离开的敌人仍会保留。雾区没有等价的矩形
负面证据。构筑物与未重访树木只保留观测事实，不作任意时间衰减。

静止实体的最后观测位置不会随时间漂移；只有已观察到运动的实体才会扩大位置不确定范围。
`party_state` 公开队友总数、存活队友数和存活队友索引，但不公开不可见队友的位置或隐藏行为。原版
实体池可能复用节点来生成新的材料或消耗品，记忆层会根据位置可达性分配新的 `memory_record_id`，
避免覆盖旧记录。

因此，全图决策使用“当前可见信息 + 永久观测记录 + 带置信度的当前存在信念”。从未看见的实体不会
进入记忆，远处实体也不会因为留有记录就被视为确定存在。

### 运动状态

观察器优先保留原版为可见实体维护的当帧物理速度；原版没有提供权威速度时，才根据连续可见位置计算
后备速度。加速度统一由连续速度样本估计，并经过平滑和限幅。规划器用快速衰减的加速度模型短时外推
弯曲或变速趋势；首次看到、观察中断或样本不足时自动退化为当前速度或匀速预测。该过程不读取移动目标、
攻击目标、随机状态或未来行为。

当前可见的敌方投射物通过 `visible_world.enemy_projectiles` 公开以下运动字段：

| 字段 | 含义 |
| --- | --- |
| `relative_position` | 当前实际命中形状中心相对玩家的位置；动画位移命中形状时不退回弹体锚点 |
| `velocity` | 当前基础世界坐标速度；解析运动模型的速度偏移另行叠加 |
| `acceleration` | 由连续可见样本估计并经过平滑、限幅的世界坐标加速度 |
| `motion_confidence` | 加速度趋势的可信权重，范围为 `0.0–1.0` |
| `visual_radius` | 从可见外观估计的半径 |
| `contact_radius` | 完整世界变换后包围实际命中形状的有限半径；敌方投射物观察契约的必需字段 |
| `motion_model` | 已形成弹道的解析运动模型；正弦弹公开速度振幅、角频率和当前相位，普通弹为线性模型 |
| `contact_damage` | 当前可见投射物一次命中的原始伤害，用于生命风险预算 |

敌人通过 `enemy_tracks` 公开当前估计位置和以下运动状态：

| 字段 | 含义 |
| --- | --- |
| `relative_position` | 当前可见位置，或离开视野后的估计位置 |
| `last_observed_velocity` | 最后一次可见时测得的速度 |
| `last_observed_acceleration` | 最后一次可见时估计的加速度 |
| `estimated_velocity` | 将已观察加速度衰减到当前时刻后得到的速度估计 |
| `estimated_acceleration` | 衰减到当前时刻的加速度估计 |
| `motion_confidence` | 用于加速度外推的可信权重；离开视野后持续降低 |
| `seconds_since_seen` | 距最后一次可见的秒数 |
| `uncertainty_radius` | 离开视野后随时间和速度扩大的位置不确定半径 |
| `recency_confidence` | 最后视觉位置仍可用于空间决策的置信度；不会被血条状态刷新 |
| `existence_confidence` | 当前仍存活的置信度；持续血条目标在失视期间保持为 `1` |
| `persistent_health_observation_active` | 当前是否由原版持续血条观察提供存活与生命状态 |

速度和加速度分别使用世界坐标单位/秒与世界坐标单位/秒²。`motion_confidence` 只调节没有解析机制时的
加速度趋势；速度仍作为最低阶运动估计。观察层优先保留原版为可见实体维护的当帧物理速度；仅当原版
没有提供权威速度时，才以连续可见位置差分补足。正弦横摆一类已形成的稳定曲线弹道由当前相位、速度
振幅和角频率唯一确定，规划器直接积分原版速度方程；发射方向、散布或速度的随机结果在弹体出现后已经
体现为可见基础速度。尚未发射且仍含随机分支的未来弹道只保留机制区间，不读取随机结果。规划层消费
`estimated_velocity` 和 `estimated_acceleration`，而
`last_observed_*` 字段保留最后一次可见时的测量，供诊断和记忆解释。

敌人稳定机制还可形成 `behavior_profile.target_position_response` 与
`behavior_profile.charge_attack`。前者描述移动行为是否响应目标位置、稳定移动速度、偏好距离，以及进入
偏好距离内后停住还是向外恢复距离。规划器沿候选玩家路径分步积分该响应，近似原版逐物理帧重新归一化
方向的语义；没有稳定响应机制或敌人已经进入锁向高速运动时，改用观测运动外推。后者描述冲撞的触发
距离、速度、持续时间、可达距离、稳定冷却区间和目标分布。
`next_charge_attack_window` 与齐射时间窗采用同一公开规则：确定冷却给出精确时间，尚未完成的随机冷却
只给出稳定区间；冷却归零并已形成可见攻击准备时公开立即就绪。对尚未揭示随机瞄准结果的冲撞，规划器
保留目标区域的概率分布，以固定五点矩匹配求积近似各候选的交会风险，并在每个求积点解析计算 TTC；
只有实际到达相应时域的概率质量才进入导航、动作预测或提交期风险。冲撞已经形成可见高速运动后改由
观测路径拥有，避免重复计值。
横向脱离、沿线停留或径直后退的差异由相对运动和到达时间产生，不编码闪避动作方向。
对齐射时刻精确、朝向目标、弹速和射程稳定的攻击，环境模型会在弹体生成前按稳定投放方程形成
候选相关的未来射击走廊；候选离开走廊后压力自然下降。方向仍含随机分支、时刻只有区间或投放模式不
朝向目标时，只保留各向同性的远程火力压力，直到可见弹体公开已经实现的轨迹。
这些版本知识无需以本局受击为前提。

可见树木的 `destructible_profile` 公开稳定的最大生命、破坏命中上限和 `death_rewards`；死亡奖励画像包含
材料数量、基础消耗品掉率、消耗品成为箱子的条件概率及必掉条件。其中 `destruction.hit_limit` 表示命中
上限而不是预计完成需求。`destruction_state` 公开可见时原版剩余生命、已受击数与距上限的剩余命中数，
离开视野后作为最后一次合法测量随实体记忆保留。稳定机制、可变状态和玩家状态彼此分离：
幸运、当前生命、一击树或保树效果只在规划层换算成当轮边际价值。

玩家自身的 `movement.velocity` 保留物理体报告的当前速度用于诊断；`movement.knockback_velocity` 则直接
读取原版 `Unit.get_next_velocity()` 使用的击退分量，且是运动学预测中外部扰动的唯一来源。这样玩家
生成定位导致的单帧物理体速度不会被误判成击退并外推到候选路径。

### 友方角色与构筑物

可见构筑物由 `visible_world.structures` 单独表示，并带有与投射物相同的当前运动字段；这使游走机器人
一类移动作用区也只能按已观察运动外推。`influence.combat_support` 描述炮塔射程、地雷一次性爆炸区或
减速场，`influence.healing_support` 描述治疗覆盖；战斗支援分别公开玩家启用半径、玩家/敌人触发半径，
避免把持续启用条件与一次性触发事件混为一谈。公共画像还公开作用半径、相对强度、是否一次性、
同时目标容量和是否依赖恢复机会。花园已经生成的果实通过可见消耗品参与规划，不把未知冷却或未来产出
提前计分。

其他玩家和宠物统一由 `visible_world.allied_agents` 表示，公开 `kind`、归属玩家、与当前玩家的关系、
可见运动字段和作用画像。规划器消费压力减免区、治疗区、投射物拦截区，以及其他玩家实体碰撞压力；
不接收“战斗支援”“治疗者”“拦截者”等角色标签。没有完整且合法的协作状态契约时，也不产生额外的
靠近收益。

### 敌人行为画像

场景节点只在观察层内部充当连续性标记，不会进入公共观察。敌人的 `behavior_profile` 由
`EnemyMechanicCompiler`、`EnemyAttackTimingObserver` 和 `EnemyBehaviorProfiler` 依次构建：机制编译器从可见
敌人的稳定配置编译攻击、位置响应、耐久和战场后果，其中位置相关机制委托给
`EnemyMotionMechanicCompiler`；攻击时序观察器形成当前的下一轮齐射与冲撞时间窗；画像器再融合稳定机制、
当前时序和未知内容的本局发射归因。稳定内容 ID 只作为编译器的内部缓存键；公共观察不包含内容 ID、
场景节点。死亡奖励画像在每次可见测量时另行适配，以纳入当前数量期望和单位效果，不进入按内容
缓存的稳定机制。可见敌人的当前生命作为 `last_measurement.health` 中的战斗期测量公开；普通敌人离开视野后
保留最后合法测量。原版持续血条可感知的 Boss/Elite 则通过独立持续血条观察继续刷新当前生命和存活，
但该观察不刷新视觉位置。稳定最大生命仍由机制画像提供，两者不得混入同一缓存。
观察器使用原版 `EntitySpawner.get_all_enemies()` 的合并域，因此普通敌人、精英与 Boss 进入同一轨迹
协议；模型不根据容器或身份另设策略。

因此，具有 `ShootingAttackBehavior` 的可见敌人会立即贡献已确认的远程火力压力，无需等到它在本局
首次开火。敌人节点下常驻的敌方投射物也会编译为 `attached_orbit` 压力并进入可见弹道观察，覆盖
腐化树和 `predator` 一类不经过主敌方投射物容器的危险。对没有标准攻击配置的扩展内容，附近出现并
向外运动的可见敌方投射物仍可形成基于观察的发射归因；它与稳定机制编译是两种证据来源，不用于填补
缺失的碰撞几何。该证据随敌人轨迹保留，并在轨迹过期时消失。

`enemy_tracks[*].behavior_profile` 公开规划所需的稳定机制与观察结论。运动预测可以依据已确认机制选择相应
的运动方程，但该差异只属于状态估计：下游风险、机会和导航统一消费预计时空状态，不据此形成敌人类别、
固定目标或行为优先级：

| 字段 | 含义 |
| --- | --- |
| `projectile_attack` | 投射物攻击类别、知识来源、置信度、射程、投射物参数、射击间隔、随机边界、投放模式和火力强度 |
| `next_volley_window` | 下一轮齐射时间窗；确定性冷却给出精确时间，随机冷却只给出稳定区间 |
| `target_position_response` | 敌人对目标位置变化的连续移动响应、偏好距离、距离内响应方式和稳定速度 |
| `charge_attack` | 冲撞的触发范围、速度、持续时间、最大可达距离、冷却区间，以及玩家位置与玩家周边随机区域的目标权重和范围 |
| `next_charge_attack_window` | 当前下一次冲撞时间窗；确定性与随机冷却的公开规则同齐射时间窗 |
| `durability.maximum_health` | 稳定机制提供的最大生命基准 |
| `contact_radius` | 敌人标准圆形接触伤害形状的实测半径；稳定机制画像的必需字段 |
| `contact_damage` | 当前可见敌人的接触伤害 |
| `death_rewards.material_quantity` | 目标版本 `get_stats_value()` 返回的当前确定材料数量，再乘以当前单位机制决定的材料倍率；不含材料掉落概率 |
| `death_rewards.material_drop_guaranteed` | 是否绕过敌人的波次材料掉落概率；树木和原版强制材料掉落目标为真 |
| `death_rewards.base_consumable_drop_chance` | 原版配置提供的任意消耗品基础概率，尚未结合当前幸运等状态 |
| `death_rewards.item_box_conditional_chance` | 已产生消耗品时成为箱子的基础条件概率，尚未结合当前幸运等状态 |
| `death_rewards.consumable_drop_guaranteed` | 是否绕过任意消耗品的概率判定 |
| `death_rewards.guaranteed_death_products` | 死亡必定产生的可见产物类型及原版最大生成位移 |
| `death_rewards.stat_changes` | 死亡结算确定施加的属性、运算与数值；规划层按当前状态计算边际价值 |
| `battlefield_effects.hostile_population_per_second` | 敌人存活期间按稳定攻击机制生成敌人的速率 |
| `battlefield_effects.maximum_lifetime_hostile_population` | 有限次生成机制在完整生命周期内的稳定生成上限；无限机制为 `null`，不表示当前剩余次数 |
| `battlefield_effects.amplification_*` | 每秒强化激活数，以及每次激活施加的生命、伤害和速度比例 |
| `battlefield_effects.enemy_healing_base`、`enemy_healing_per_wave` | 敌人进入治疗触发区时的基础治疗量与逐波增量 |
| `battlefield_effects.player_healing_base`、`player_healing_per_wave` | 玩家进入同一治疗触发区时的基础治疗量与逐波增量 |
| `battlefield_effects.enemy_healing_radius` | 敌我治疗共用的实际触发区半径 |
| `material_assimilation` | 材料吸附与拾取半径、进化材料阈值及最高耐久倍率；存活负担解除价值由当前材料竞速几何派生，不包含敌人类别优先级 |
| `removal_effects.visible_projectile_damage` | 与来源一同删除的当前可见投射物原始伤害总量 |
| `removal_effects.spawned_hostile_population` | 击杀该敌人会立即生成的稳定敌人数；它作为死亡后果进入独立成本通道 |

`enemy_tracks[*].last_measurement.health` 公开当前合法感知的 `current`、`maximum` 和 `ratio`：普通目标来自
最后一次视觉测量，持续血条目标则在视野外继续更新。敌人完成需求和局部武器伤害上限使用该剩余生命；
完成价值按当前单次伤害对应的 `ceil(剩余生命 / 单次伤害)` 离散击打次数兑现，溢出伤害不产生额外价值。
字段缺失时才退回稳定最大生命先验。这样残血目标自然具有较低的完成成本，同时不会用持续血条观察凭空
制造位置精度。

敌人机制画像还可声明 `death_rewards.guaranteed_death_products`。该契约同时包含原版生成产物相对死亡
位置的最大位移。观察层只处理首次看见、类型一致且位于失视目标机制支持域内的产物；仅当这个产物在已
追踪目标中只有一个合法来源候选时，才把它作为足以结清轨迹的死亡证据。多个目标共享同一支持域时保持
未知，不按最近距离强行认领；每条目标轨迹最多消费一个产物。静止树木则长期保留已知位置和最后破坏
状态，直到重新覆盖该位置确认其不存在；确认不存在的实体和已结清敌人不会进入规划快照。

`projectile_attack.knowledge_source` 区分 `stable_mechanics` 与 `observed_emission`。前者是目标版本的稳定
机制知识；后者是已经观察到发射行为后形成的局内证据，只补充远程压力画像，不补充稳定机制或碰撞字段。

### 地图定位

`localization` 从移动里程计开始。看到左侧或上侧地图边界后，才能逐轴确定地图坐标；其他已见边界用于
补充当前边缘距离和已知地图尺寸。观察记忆还以四分之一短边视口为网格尺度记录合法视野覆盖。该网格只
描述“何处曾经可见、距今多久”，不记录格内隐藏内容，也不读取尚未观察到的完整地图位置。

| 字段 | 含义 |
| --- | --- |
| `odometry_position` | 从本局初始位置累计的玩家位移；不要求地图边界已经定位 |
| `map_x`、`map_y`、`map_position` | 看到对应左侧或上侧边界后才能确定的地图坐标；未知轴为 `null` |
| `map_bounds` | 四条边是否已见、当前距已见边界的距离，以及可由两侧边界确定的地图尺寸 |
| `observation_grid_cell_size` | 由首次有效视口短边的四分之一派生的正方形观察网格边长 |
| `observation_cells[*].grid_x`、`grid_y` | 已被合法视口覆盖过的里程计网格坐标 |
| `observation_cells[*].seconds_since_observed` | 该网格距最近一次合法视口覆盖的秒数 |

覆盖计算使用 `visibility.viewport_size` 与 `viewport_offset_from_player`，因此视口不以玩家为中心时仍沿用
实际可见矩形。未出现于 `observation_cells` 的网格表示尚无合法覆盖记录，不表示其中安全或没有实体。

## 机制知识

机制知识按信息所有者适配或编译。外部实体只有通过可见性判定后，才能调用对应知识模块；玩家自身的
透明效果数据则直接进入玩家效果适配边界。

### 敌人机制

`EnemyMechanicCompiler` 是敌人可见后稳定机制的聚合入口。它直接编译投射物攻击、耐久、接触伤害与
接触形状、奖励和战场效果，并委托 `EnemyMotionMechanicCompiler` 编译目标位置响应与冲撞。Boss 各阶段
攻击和普通敌人的附加攻击统一从 `_all_attack_behaviors` 聚合。稳定配置可以包含攻击区间和随机边界，
但不包含本轮已经抽取的结果。

当前攻击时序归观察层的 `EnemyAttackTimingObserver` 所有，并分别形成 `next_volley_window` 与
`next_charge_attack_window`。确定冷却公开精确时间，未完成的随机冷却只公开稳定区间，已经可见的攻击
准备公开立即就绪；当前目标、当前生命和随机状态不进入稳定机制画像，其中当前生命由观察层作为可见
测量单独公开。公共字段及其含义由前文的
[敌人行为画像](#敌人行为画像)定义。

目标版本的敌人清单、树木完成机制、投射物形态、实现映射和升级复核步骤见
[原版敌人、树木与投射物机制参考](vanilla-enemy-mechanics.md)。目标游戏版本的覆盖结论独立于架构契约维护。

### 玩家效果规则

原版先把玩家携带内容聚合为 `effects`。`bot/knowledge/player_effects` 是这套目标版本存储格式的适配边界，
只把已理解的字段翻译为统一规则。每条规则由事件、作用于事件载荷的条件和状态变换组成；条件描述可组合
事实，状态变换使用 `target`、`operation` 和参数表达。规则的支持范围由这些正交轴定义，不以角色、
物品、武器或扩展内容的目录衡量。

`PlayerRuleProjector` 沿上述轴产生恢复、生存与动作状态的规则投影，结果预测器则把
同一规则应用到候选路径。两者都不能读取原版字段名或内容 ID。可见消耗品同样只公开基础恢复量和语义
特征；实体特征由通用条件匹配，不以“能否触发某项机制”的布尔字段扩张观察契约。

`StatOpportunityProfileAdapter` 把属性影响未来事件概率的目标版本参数适配为
`stat_opportunity_profiles`。曲线参数属于版本知识；材料等价基准和剩余机会时域属于规划层估值。

### 武器攻击模型

武器由 `bot/knowledge/weapons/weapon_mechanic_compiler.gd` 读取目标版本的运行时状态和效果资源，编译出
不含节点、内容 ID 或机制名称的 `attack_model`。参与决策的最小契约是三个正交状态轴和一套状态转移语言：

| 轴 | 回答的问题 |
| --- | --- |
| `timing` | 当前可感知冷却、攻击进行状态与长期交付速率，包括长装填折入后的期望周期和移动许可 |
| `delivery` | 能把命中投送给谁，以锁定距离、最大飞行距离、飞行速度、路径数、角覆盖、走廊宽度、方向误差、路径容量、伤害保留、重定向选择与容量表达 |
| `impact` | 一次基础命中产生多少伤害、暴击和生命偷取，以及受哪些玩家属性缩放 |
| `rules` | 状态转移语言：已定义事件如何变换前三轴或产生结果，由事件、条件和状态变换组成 |

暴击增加贯穿、持续伤害、邻近目标伤害、重新选目标伤害和按目标耐久补足伤害都只是
`rules` 中已有轴的组合，不会成为新的决策维度。原版 `Effect` 子类只允许在编译器中决定如何翻译；规划层
只解释事件、条件、目标、操作、数值来源，以及目标与触发位置间的空间和容量约束。

玩家与武器的 `rules` 使用同一 `consequence` 契约：`probability` 表达发生概率，`target` 与 `operation`
表达状态转移，`amount` 是常量及已建模状态量的线性组合，`delivery` 只含目标选择、是否复用或排除事件
目标、是否以事件实体为锚点、半径、飞行速度、最大飞行距离和每事件容量。
`minimum_targeting_distance` 与 `maximum_targeting_distance` 以目标中心距离界定自动锁定范围；目标版本的
`Weapon.should_shoot()` 在 `current_stats.max_range` 外另有固定 `50` 像素准入量，由武器机制编译器统一写入
`maximum_targeting_distance`。目标外观半径不得扩大锁定区，只能参与命中路径的几何交会；接触半径仍
专属于伤害碰撞。
`maximum_travel_distance` 则界定路径或后续事件的传播距离。版本知识模块可以识别原版机制来编译这些量，
任何规划器都不能据此恢复或分派机制类别。

### 攻击模型的当前边界与扩展条件

公共攻击模型尚未覆盖以下三类能力。下表同时规定当前行为、重新设计的条件和责任边界；它们不是按内容
名称积累的适配待办：

| 问题 | 当前决策 | 重新打开设计的条件 | 所有者 |
| --- | --- | --- | --- |
| 非武器自主伤害源 | 当前结果预测只汇总玩家武器；不把周期弹幕或击杀派生攻击塞进物品规则特例 | 该来源能稳定改变移动位置上的期望结果，且可从合法状态估计其单位时间容量 | 将 `attack_model` 泛化为通用攻击源的 `bot/knowledge` 机制编译器与结果预测模型 |
| 目标条件伤害 | 当前生命已作为可见生命测量用于完成成本，但 `impact.rules` 尚未编译按当前生命追加伤害或依赖其他目标状态的连锁 | 条件能够由合法目标测量表达、跨内容复用，并有通用规则容量模型 | `bot/observation` 的统一目标测量与武器规则编译器；版本映射模块不得自行读取额外目标状态 |
| 命中后的运动反馈 | 当前动作内的敌人轨迹不因尚未发生的击退、减速或扩散效果而改写；下一次重规划使用新观测 | 游戏内回放能校准通用状态转移，并证明它会实质改变动作排序 | 运动观察与动作期状态转移预测器共同拥有，不能由单个效果修补轨迹 |

没有单独列为扩展点的行为已经由现有契约决定：敌人完成价值使用最后观测剩余生命形成完成份额，缺失时退回
最大生命先验；一次攻击只对其
预测时刻已存在的合法目标计分，不猜测返程前可能新入场的实体；预测窗外的周期属性、波间收益和随机升级
不提前计分，实际生效后由下一次观察和重规划自然接管。

新增能力优先组合已有的事件、条件和状态变换。只有共享模型缺少必要表达能力时才扩展正交轴，
并使现有规则能够自然复用。目标版本的原版字段映射只是局部适配代码；本文只描述规则轴、预测语义和
扩展条件；按内容核对的版本覆盖分别由敌人机制参考和玩家效果与武器机制审计维护。

### 友方与构筑物作用画像

`AllyMechanicCompiler` 与 `StructureMechanicCompiler` 把可见玩家、宠物和构筑物编译为同一类数值化
作用区；它们可以在机制编译边界识别原版类型，但规划层只接收几何、强度、启用条件、触发条件、容量和
恢复机会约束。
两者都不读取当前目标、冷却、生命或未知的未来产出。

## 滚动规划

规划器采用受计算预算约束的滚动时域控制近似。动作 `u` 的效用由短预测窗内的环境暴露、条件生命风险、
条件战斗与事件结果，以及动作窗外的导航轨迹价值组成。位置域扫掠与速度障碍在完整
局部窗内保留远期交会诊断；只有发生在候选动作自身预测窗内的交会才换算为该动作的条件生命成本。
控制期是由六个物理 tick 派生的名义重规划间隔；提交期是候选在新观察到来前实际执行的部分，并受
控制期、动作预测窗和本波剩余时间共同裁剪。控制器每次只执行一个提交期，然后用新观察重新求解。

### 决策流程

每次重规划依次执行以下步骤：

1. 控制器提供由实测物理回调峰值形成的帧预算上下文。规划器先用保守位移上界排除在导航时域内无法影响
   玩家可达区域的投射物。完整敌人轨迹仍参与全局价值与导航；局部动作评价另以玩家位移、敌人观测速度、
   加速度、稳定追踪/冲撞速度、位置不确定范围、压力作用半径和武器锁定距离构造敌人交互域。能够在动作
   窗内威胁玩家的轨迹会保留；可见轨迹还会在能够进入自动武器锁定区时保留。其余远程轨迹只参与导航、
   敌人完成价值与波内完成预测，不进入不会受其影响的局部动作精算。计算预算政策再把每位存活玩家可用的
   控制窗聚合帧余量转换为最终截止和连续预算压力。动作生成器保留由碰撞几何派生的局部均匀动作；搜索
   工作分配器随压力在四至八个均匀方向间分配近似战略导航基线，并收缩额外角区间细化和机会评价。
   局部均匀动作、零输入和碰撞时间采样不受该预算削减，因此预算不会删除由动作几何提供的基础机动覆盖。
2. 导航意图规划器先比较均匀基线方向，再以机会聚合方向和优胜角区间细分扩大预算内搜索。每个实际评价
   的方向都沿完整可达轨迹在多个未来时刻采样，比较材料、恢复、拾取规则完成价值、可见未来事件、
   导航武器完成价值和环境暴露的时均差，
   以及沿途去重累计的地图信息。
   动态敌人与环境暴露都以同一未来时刻的零输入状态为反事实基线，只把玩家移动实际改变的部分归给动作。
   地图项使用沿候选轨迹的视口扫掠并按网格去重，再按观察陈旧度计价：未见网格具有完整再观察
   价值，已见网格随距上次观察的时间连续恢复该价值。因此未知区域产生探索，地图全部定位后也会自然
   巡游较久未观察的区域，无需预设巡逻路线。只有正增益轨迹会形成移动偏好。
   这是滚动时域控制的场采样近似：搜索层比较可达轨迹，状态价值层在轨迹各时刻估计当前武器通过最近
   目标和额外投送路径可兑现的目标完成价值。控制器仍只执行一个控制期并重新观察，因此不展开
   远期动作树，也不使用退火或随机采样替代已有的几何结构。
3. 导航风险使用与局部生存效用相同的环境风险单位价值。当前生命、防御、下一控制期内可达的最强一击
   和清场前可兑现的生命补充共同决定该价值。敌人耐久先按当前武器组合的平均主路径单次伤害换算为命中
   需求；树木则取按伤害耗尽剩余生命、达到命中上限或触发一击树效果所需命中数中的最小值，再进入同一个
   主路径攻击容量账本。逐目标独立估算只形成命中需求；所有目标分配的期望命中数之和不得超过
   本波剩余攻击容量。因此拥挤场景不会把同一段未来火力同时预支给每个
   普通敌人、特殊掉落敌人和树木；高奖励与低完成成本仍通过统一边际价值自然形成偏好。本波剩余时间只
   影响补充与收益能否兑现，不直接折价生命。
   动作生成器离散化本次可提交的移动输入，并补入已经通过轨迹评价胜出的导航方向。未经完整轨迹评价的
   搜索提案不会直接进入动作集。零向量是不输入移动指令的动作。
4. 动作只会执行到下一次重规划。提交期由整数物理 tick 派生；近端预测窗为两个控制步。
   局部默认窗至少包含四个控制步，且足以跨越两个玩家碰撞直径；局部上限再保留三个修正步，
   导航窗再延伸五步。动作、导航、速度障碍和投射物可达性使用的有效时域都截断至本波剩余时间，
   不会给波次结束后无法发生的收益或碰撞计价。动作生成器以玩家完整动作集合和已知威胁运动上界做时域
   扩展广相筛选：筛选命中时，候选统一在局部上限上比较；否则统一使用局部默认窗。该筛选只决定共同
   比较时域，不宣称威胁必然命中，也不替代步骤 1 的局部敌人交互域过滤。预测窗不取决于上一条移动输入
   与敌人当前速度是否恰好呈线性交会，较近威胁也不会反向截短时间域。角向分辨率使相邻指令
   经过一个提交期后的端点间距不超过玩家半径；时间采样使相邻玩家位移不超过碰撞直径，确定性曲线弹的
   相位步长不超过 `π/2`。
5. 每个动作只在上述敌人交互域中生成一次战场、速度障碍和事件基础结果，再由
   [武器结果预测](#武器结果预测) 沿该动作路径计算下一决策状态的修正，然后进入唯一一次完整评分。
   候选方向不会展开逐发攻击过程。
   普通敌人接触由目标位置响应后的敌我相对线段扫掠负责；投射物也使用扫掠线段，避免高速实体穿过采样
   间隙。扫掠线段一旦穿过标准碰撞边界就形成完整接触机会，穿入深度不再充当命中概率。解析速度空间
   证据只保留弹道 TTC、队友碰撞，以及尚未发生冲撞的目标分布与解析 TTC；几何风险取两类证据的较大值，
   不再用恒速 TTC 重复近似会持续转向的普通敌人。稳定目标位置响应使用嵌入式二阶中点步长加倍：完整步
   与两个半步的位置差决定收紧或放宽步长，直到达到位置误差目标或统一的最小步长。该最小步长保证单次
   积分有界终止；所有候选使用相同参数，不随帧预算或可选搜索额度切换。
6. 位置扫掠为敌人与投射物交会公开按来源区分的 `contact_opportunities`，每条机会保留预测时刻
   `time_seconds`、来源 `source_id`、兑现概率 `realization_probability`、原始伤害及来源是否在接触后消费。
   生命模型从已观察的当前无敌剩余时间开始，按原版顺序逐机会推进闪避、命中保护、护甲、实际伤害和
   随伤害变化的后续无敌时间，由同一状态分布得到预期生命损失与累计终止概率。这样连续亚致命命中是否致死取决于
   它们的时序和中间状态，不依赖“一击或两击致死”策略。尚未公开逐次时刻的速度空间交会仍保留峰值风险、累计接触和
   原始伤害加权证据作为兼容账户；位置与
   解析证据取较强结果，避免重复覆盖同一交会。聚合期望量本身不再被解释为独立命中的概率分布。局部碰撞
   生命成本对消耗后的即时生存缓冲积分，越接近缓冲耗尽，边际成本越高。
   超过当前即时生存缓冲的期望损失部分改用终止生命损失单价，仍只在生命库存账本中计入一次。完整预测
   窗内的生命损失仍按即时生存缓冲计价；提交期内的终止风险和缓冲消耗比例另按当前对局延续价值
   计价。该价值由持有材料、已有道具和武器的替代价格代理组成，使已经落入控制承诺的风险随死亡会清除
   的对局进度自然变贵。条件恢复仍进入公共效用，但在实际观察为当前生命前不降低同窗碰撞损失，避免
   连续规划重复借用同一份未来恢复。
   提交期终止风险为 `1` 时，候选会在下一次重规划前死亡；若存在风险小于 `1` 的替代动作，该候选不再
   具备执行资格。提交期内的非确定终止风险另按对局延续价值计价；提交期后的风险只保留预测窗生命损失与环境
   暴露成本。两者都与攻击、存活负担解除、恢复、材料和信息收益在公共效用账本中交换。
7. 在最终截止与当轮搜索工作分配给出的额度内，规划器围绕当前具有执行资格的高分动作，在相邻角区间
   插入中点；每个新候选也执行与基线相同的完整预测和评分。预测窗内的条件生命风险与其他结果一样参与完整
   细分。可选搜索额度改变候选覆盖，不改变候选之间的结果语义。
8. 选择器先应用上述提交期执行资格，再选择统一账本总效用最高的动作。控制器提交所选移动向量，下一次
   规划重新读取环境。方向仍由碰撞、攻击、存活负担解除、恢复和可失去的对局延续价值共同决定；执行
   边界不编码敌人数量、生命阈值或逃跑方向。生命窃取与拾取恢复兑现到下一观察后，会自然改变生命库存
   价格。

### 决策基底

进入最终动作选择的量按责任而不是按数据来源划分为最小基底：环境暴露、碰撞风险、条件事件结果、
期望武器结果和尚未兑现的导航行程价值。一个事实可以被多个预测器观察，但只能由一个
评分量拥有其决策含义：位置扫掠和 VO 都是碰撞检测证据，合并后才计分；候选路径进入收集半径的消耗品
形成 `expected_recovery`，并由 `consumed_consumable_recovery_supply` 结清离开地图的恢复储备；满血或溢出
拾取造成的恢复机会损失另由 `wasted_consumable_recovery` 诊断。已经落地的箱子会在波末自动收集，其道具
选择不因战斗中提前拾取而新增，因此导航只计算即时回血和拾取事件。树木或敌人尚未生成的箱子则属于击杀
收益，按箱子实际生成概率计价。动作预测窗内的拾取、承伤、路径规则和武器结果都是持续采用候选输入时的
条件结果，不宣称提交期外的事件已经发生；提交期碰撞子集另行保留为即将执行的诊断。更远结果只能由环境
暴露、远期碰撞诊断或导航轨迹价值表达。`material_acquisition_value` 只拥有候选路径上的实际收集，并按
可见材料的确定数量结算；尚未拾取材料的空间价值由导航统一聚合。局部动作以原版收集半径和连续相对交会
判断实际拾取；导航在各轨迹采样时刻以同一收集半径比较可达性，形成平滑机会梯度。已经处于收集圈内的
材料由局部结果结算，不再由导航重复定价；进入吸附范围但尚未进入收集圈时，仍保留继续接近的机会梯度。
所有候选都相同的被动恢复只影响规划上下文，不进入动作结果。

效用模型把评分字段唯一分配给五个决策目标：`survival`、`recovery`、`economy`、`combat` 和
`navigation`。调试构建在每个效用模型实例首次生成评分上下文时验证同一字段不能进入两个目标；
`objective_utility_breakdown` 公开目标级总账，`field_utility_breakdown` 保留字段级解释。规划空间不是先把
世界烘焙成两张标量栅格再相加，而是在候选位置与时刻查询一个多通道场。环境威胁、材料、恢复、拾取
规则完成价值、导航武器完成价值和地图信息先由各自所有者换算，再到导航轨迹聚合价值中相加。这样既能诊断“高奖励但高威胁”，
也不会让不同单位、时域或条件的量在进入模型时就失去含义。

敌人完成状态转移保留三个正交通道：奖励变化、存活负担解除和死亡后果。奖励变化等于敌人死亡奖励减去
失去的存活奖励；存活负担解除可以为负，例如完成一个会治疗玩家的敌人会失去未来治疗；死亡后果记录死亡
触发的新敌人等成本。`EngagementTargetProjector` 把敌人轨迹与树木统一投影为可交战目标。树木静止、
不响应玩家位置，没有存活负担或死亡后果，完成条件取生命归零、达到命中上限与一击树效果中最先满足的
一项；普通敌人、精英、Boss 与宝箱怪则由同一敌人机制画像提供运动、耐久、收益和负担。波内完成预测以
统一的 `target_id` 给出有界 `completion_fraction`；局部武器结果预测按原版最近目标顺序和投送路径分配
同一目标集合的命中容量，再按目标声明的离散剩余击打次数或命中上限进度兑现完成价值。
`expected_enemy_completion_equivalents` 与
`expected_tree_completion_value` 保留不同结算单位，但都只是容量代理，不是经过统计校准的击杀概率。
空间机会模型在候选轨迹采样状态统一计算原版最近目标、持续移动可形成的锁定窗口以及武器的额外群体容量；
局部武器预测仍负责动作窗内已经能够发生的攻击结果。任何一层都不包含树、精英、宝箱怪或
Boss 的预设身份优先级；追击顺序只由上述机制在当前状态下的价值与可达性共同产生。
移动不会把拾取与自动攻击拆成互斥目标：每个候选移动同时比较导航路径上的材料、恢复、导航武器完成价值
和该路径允许的局部武器结果；动作预测窗内的交互只记为采用该候选输入时的条件结果。无稳定目标响应的
敌人沿用观测运动外推；已确认追踪响应的敌人则按候选玩家路径逐步更新方向，因此追踪经验会改变地图和
轨迹评分，却不会变成预设动作。
移动状态产生的材料周期收益归入 `economy`；护甲、闪避、武器属性和移动速度分别进入生存、攻击与
运动学预测器。

规划时间域由 `MovementTimingModel` 唯一拥有：它从物理 tick、控制步数、玩家碰撞直径和当前速度派生
提交期、局部动作预测期和导航预测期。空间机会的评分归属则由 `SpatialOpportunityValueModel` 统一处理。
已确认不存在的记忆不进入机会模型；所有仍可能存在的可见与记忆机会都由导航路径统一计值，不再按局部
半径分账。导航武器完成价值描述轨迹采样状态下的后续完成机会，不替代候选动作对局部武器结果预测的采样。
动作集合包含离散方向和零输入。目标版本 `Unit.get_move_input()` 将非零移动输入归一化后乘移动速度。

而不是使用波次阶段的独立倍率。一单位材料是基础价值基准；合并材料和奖励材料按外观

独立通道中。

### 暴露与导航意图

底层环境暴露 `P(x,t)` 是位置和时间上的连续启发式运行成本，不声称是物理压力、受伤概率或完整价值函数。
`NavigationIntentPlanner` 在有效导航时域内的可达轨迹上采样该场，用于比较大方向而非精确避弹。均匀
方向保证没有已知机会时仍能比较空间；机会聚合方向和连续角区间细分都属于
预算内搜索提案。它们只增加采样覆盖，必须经过完整轨迹评价才可能影响动作，不预选策略目标。候选轨迹
受本波有效导航时域和已知边界裁剪。

本文使用以下术语区分搜索位置、价值与可执行输入：

| 术语 | 含义 |
| --- | --- |
| 场采样 | 在未来状态 `(x, t)` 比较候选移动与同刻零输入反事实的材料、恢复、可见未来事件、武器完成和环境暴露差 |
| 轨迹聚合价值 | 沿一条可达轨迹聚合场采样，并加入沿途去重的地图信息价值 |
| 访问势能 | 尚未进入收集圈或武器射程时，由截止可达性和距离衰减形成的状态价值；只评价可达状态，不替代动作结果中的收集、命中或完成 |
| 搜索提案 | 只指定额外评价方向；本身没有价值，也不是可执行动作 |
| 移动偏好 | 轨迹聚合价值为正的最高分已评价方向；只有它可以补入局部动作候选 |

地图信息模型沿轨迹扫掠视口，并按观察网格去重：未见网格贡献完整覆盖变化，已见网格按距上次观察的
时间相对波长连续恢复。它只计算合法视野中新增或恢复的规范化覆盖，不把未知区域视为已知安全区，也不
编码巡逻路线。效用上下文为覆盖变化提供每视口信息单价：先取基础下限、当前可见机会均值与潜在单个
消耗品恢复量的补给库存价值中的较大者，再按本波剩余比例裁剪。生命越稀缺，揭示恢复机会的价值越高；
沿途环境暴露仍按同一生命价值定价风险。这一连续交换不设置低生命模式，也不预设树木、恢复物或探索方向。

导航把候选输入展开为可达轨迹，在多个未来时刻采样尚未兑现的材料、恢复、可见未来事件、武器完成价值
和环境暴露，并沿整条轨迹对地图信息去重累计。即使有效导航时域很短，每条非空轨迹也至少包含一个波末
前采样和波末边界采样，避免只观察必然归零的清理时刻。材料和消耗品使用实际收集半径；拾取物按已观察速度投影到相应
采样时刻，进入吸附范围只改变其已观察运动，不提前兑现机会。各采样时刻只保留在剩余波时内仍能到达
收集圈的可达性；访问势能按有效导航距离指数衰减，并在波末可达边界连续降至零。因此远处但可及时到达
的材料仍有较小的接近梯度，无法及时到达的材料既不计值，也不占用额外方向搜索预算。波末边界只保留
已经完成的收集，因此未兑现的接近进度不会作为跨波残值。

对敌人与树木，完成份额为正且能在波末前进入任一当前武器的射程时使用同一访问势能。进入射程后该势能
饱和，由导航武器完成模型接管最近目标与投送几何，避免把接近和攻击窗口重复计价。导航武器完成价值在
每个轨迹采样状态把最近主目标与贯穿、弹射和范围副目标放在同一模型中，并按原版精确中心距离边界判断
锁定资格，再按当前移动速度和截止前剩余结果时域累计有效攻击窗口；持续接近、改变最近目标或形成群体
投送几何都由完成价值自然计价。当前冷却与已显现攻击相位确定首个攻击机会，后续机会按长期期望速率形成
连续容量。容量 `c` 完成 `k` 次所需击打的有界代理为 `clamp(c - (k - 1), 0, 1)`。主目标以及贯穿、弹射和
范围副目标共享该边界，无法在波末前完成的零碎伤害不预领击杀奖励、负担解除或死亡后果。
单体武器不会因目标密度凭空增值，次要目标的净完成价值为负时不利结果仍会保留。吸引强度来自统一奖励、
战场后果、完成工作量和武器容量，而非树木或敌人类别优先级。
可见生成警告也进入同一截止可达模型：中立事件按当前信息机会价值形成在波末前接近新可攻击事件的选择；
敌对事件按已观察敌群的有符号平均负担和当前精确截止 `resolution_window.latest_seconds`，衡量及时进入
生成延后区的机会。正负担使延后生成增值，敌群整体提供净帮助时延后生成会产生负值，没有负担证据时
则为零；模型不会补入固定吸引力，也不猜测将生成的实体身份。候选与零输入基线在各时刻使用相同运动
机制，因此敌人自行靠近只改变共同未来状态，不会伪装成移动收益。
导航环境暴露也比较同一未来时刻的反事实差值。每个已评价方向都保留轨迹聚合价值；动作评分在
相邻方向样本间线性插值单位距离价值，并按输入相对零输入在动作预测窗内造成的位移兑现。因此击退保持
为共同反事实，导航行程与环境暴露、承伤和武器结果使用同一个持续动作条件时域；控制器仍只提交一个
控制期并在新观察到来后重新求解。
导航意图公开方向与价值（`movement_preference`、`trajectory_value_samples`、`trajectory_value_gain`、
`selected_trajectory`）、评价次数和空间尺度（`sampling_radius`、`local_prediction_radius`、
`control_distance`），便于验证导航意图来源。其中
`trajectory_value_gain` 是胜出轨迹的聚合价值：机会与暴露按未来时刻平均，地图信息按轨迹去重累计；
它不是单个动作预测窗中的按距离兑现字段 `navigation_trajectory_value_gain`；
`baseline_field_sample_evaluation_count` 与 `extra_field_sample_evaluation_count` 分别记录基线和额外轨迹的
时空场采样总数；`extra_direction_evaluation_count` 与 `extra_direction_evaluation_limit` 记录预算化方向搜索
的实际用量与上限；`trajectory_sample_count` 记录每条轨迹的时间采样数；`trajectory_value_samples` 记录各
已评价方向的轨迹距离、聚合价值、单位距离价值和值分解；`selected_trajectory.value_breakdown` 与各方向
样本的 `value_breakdown` 都按 `material_opportunity`、`recovery_opportunity`、
`rule_event_opportunity`、`future_event_opportunity`、`weapon_completion_opportunity`、
`map_information` 和 `environmental_exposure` 分解轨迹价值。`sampling_radius` 是地图边界裁剪前的
轨迹长度，实际长度见 `selected_trajectory.distance`。

导航轨迹的环境暴露与局部动作使用同一延续时域暴露单价。动作评价仍以更细粒度检查完整路径并执行扫掠
碰撞检测，因此导航场不会替代局部避障。候选动作还记录环境暴露沿路径的平均变化率
`[P(x(T),T)-P(x(0),0)]/T`，即 `∂P/∂t + v·∇P` 的路径平均。

各通道的抵消关系受语义约束：友方火力只能降低当前敌人接近和远程火力造成的环境暴露，不能抵消尚未
生成的警告；投射物拦截只能降低拦截时刻之后该弹原本会造成的压力。减压不能消除实体接触、角向机动
约束或队友阻塞，也不能超过当时对应的敌对压力，因此友方作用区不会产生无上限收益。治疗和治疗增益
属于独立恢复机会，不能抹去已经预测到的伤害压力。地图边界与可达敌人圆盘共同形成遮蔽角区间并集；
重叠方向只计一次，边界的单独覆盖量仅作诊断，不再形成第二项边缘成本或放大其他敌对通道。

### 动态效用

生命价值上下文在每次规划时重建。`HealthReplenishmentForecastModel` 预测清场前可兑现的生命补充：已观察
消耗品按到达时间和存在置信度折算，概率掉落按共享攻击容量约束后的目标完成份额折算，被动恢复与生命偷取
按剩余可作用时间折算。`HealthInventoryValueModel` 将这些补充与当前生命和被动生命流失合成为补给库存；
同时以玩家完整动作集合、当前击退和威胁运动在下一控制期内的联合可达域，筛出最强接触或投射物伤害
储备。候选动作自己的扫掠与解析碰撞预测仍负责区分具体方向的接触风险。
本波剩余时间界定补充、奖励与存活期威胁能否兑现。非致命生命损失的延续成本按动作窗结束后仍需生存的
导航时域比例保留；超过即时生存缓冲的部分始终按终止成本计价，不能借波末清场消失。

当前生命扣除联合可达域内的最强一击储备后形成 `immediate_survival_buffer`；该缓冲加上清场前可兑现
补充、再扣除同期被动生命流失，形成 `projected_health_inventory`。前者和剩余延续时域共同决定局部与
导航环境暴露及动作窗内非致命生命损失的成本，后者决定补给库存及波次尺度敌人负担的边际价格。整波补给
预测没有提供候选条件的近端兑现顺序，因此不能扩大当前即时生存缓冲。动作预测窗内的非致命碰撞成本沿
即时生存缓冲的对数障碍积分，越接近缓冲耗尽，边际成本越高。接触机会按时序推进得到的期望生命损失由生命库存损失
计价；同一状态分布得到的终止风险补足期望损失无法表达的致死尾部，包括多次亚致命接触累积成的终止结果。
原版下一波按开局生命
比例重新设置玩家生命，当前值不跨越波次边界，因此波末后没有持有当前非致命生命的残值；这会自然允许在
不会越过即时生存缓冲时以生命换取仍可兑现的收益，而不是由专用“波末冒险”开关或生命阈值触发。

`RunContinuationValueModel` 估计死亡会清除的当前对局延续价值：持有材料按一比一计价，已有道具和武器
按公共价格画像中的最低正稀有度均价估算单位替代价值。模型不读取具体道具或武器身份，也不估计尚未获得
的未来收益。`MovementUtilityModel` 以提交期内的终止风险，和按提交期末剩余延续时域裁剪的即时
缓冲消耗比例中较大者，计算当前动作所暴露的延续价值；暴露比例最大为 `1`。完整动作预测窗的生命损失
仍单独按预测窗末的剩余延续时域计价。具体公式和校准证据见
[生存风险定价](model-calibration.md#生存风险定价)。

拾取消耗品把地图生命补充转化为当前生命。`expected_recovery` 按即时生命的终止价格记录动作预测窗内的
条件恢复收益，`consumed_consumable_recovery_supply` 按补充库存价格结清离开地图的储备；两者的差恰好是
从储备转成即时生存流动性的边际价值，不会再次扣除同一份供应。树木或敌人新生成的消耗品则增加补充库存，
按库存价格计值。可兑现恢复量受缺失生命上限约束。

消耗品的治疗价值取当前可兑现恢复。拾取规则产生的即时伤害、持续状态及状态期间的后续伤害增量，在局部
动作与导航中共享同一空间交付和敌人完成账本：局部动作在连续收集时刻形成
`expected_rule_completion_value`，导航按候选可达性与该时刻的事件覆盖形成 `rule_event_opportunity`。
事件价值只结算候选时刻可由公开状态支持的结果，不估计一次性事件源的跨时刻保留价值。立即兑现与保留
之间的比较属于尚未实现的跨时刻状态价值边界，其证据要求见
[仍需校准的假设](model-calibration.md#仍需校准的假设)。
属性或材料效果仍由候选拾取位置上的事件预测器计算。地面箱子与果实采用相同规则：箱子携带的道具选择会在波末自动
收集，不构成提前拾取的边际收益。

`OpportunityPricingModel` 统一把地面材料、地面消耗品、实体死亡奖励和树木保留后果换算为材料等价边际
价值。实体死亡奖励同时包含概率掉落和确定属性变化：`DeathRewardProbabilityModel` 在规划快照上组合
材料的波次与潮汐波规则、消耗品和箱子的基础概率及当前幸运；`StatOpportunityPricingModel` 按当前属性、
机会曲线和剩余波次等价数计算确定属性变化的边际价值。有限轮次对局中的持久变化会在后续波次反复影响
事件机会，不能压缩成整局仅有一次机会；无尽模式没有有限未来范围，因此使用有界的波次等价量。具体
基准和无尽模式代理见 [仍需校准的假设](model-calibration.md#仍需校准的假设)。材料
条件数量和概率保持分离，树木收益中的材料使用与
地面材料相同的本波兑现价格。
箱子的道具选择价值由主线程知识适配层根据原版波次稀有度分布、当前已解锁道具池和玩家价格修正形成，
不消耗未来随机数。所有可能生成的消耗品都按
补充库存的边际价值计价，因为箱子和果实都能治疗。道具选择与治疗描述同一个箱子结果的不同收益，不是
重复计算。因此树木因较高箱率自然具有高价值，生命越低时全部消耗品的治疗部分还会连续增值，无需增加
“优先打树”或“低血找树”的策略分支。

`EnemyCompletionValueModel` 在每次规划中一次性建立敌人完成状态转移账本。奖励变化通道记录敌人死亡奖励
减去失去的存活奖励；存活负担解除通道记录直接接触与远程压力、来源死亡可清除的当前投射物、存活期间预计
生成的敌群，以及强化和治疗现存敌群造成的负担。治疗机会以单个目标当前缺失生命和单次治疗量为上限，
再按触发区间隙与双方特征运动距离衰减；满血目标不贡献治疗负担。敌人可给玩家提供的治疗机会采用同一触发区
和距离语义。死亡触发生成的敌群进入死亡后果通道。波末保留敌人的
收益及其可给玩家提供的治疗机会分别使前两个通道减小，必要时可使通道为负。所有项先换成材料等价值；
局部武器结果预测按离散击打工作量形成的完成份额兑现三个通道；统一目标投影再把该账本与树木的零负担、
零死亡后果和破坏收益放入同一导航机会通道，并乘共享攻击容量下的完成份额。两者都是受容量约束的期望代理，
不宣称统计概率。账本构造只扫描敌群一次，动作、导航和武器结果预测共享该账本，避免每个消费者重复计算。

效用模型对 `integrated_environmental_exposure`、由 `forecast_expected_health_loss` 换算的
`forecast_health_inventory_loss_value`，以及终止风险和按剩余延续时域裁剪的即时缓冲消耗按当前对局延续价值换算的
`committed_run_continuation_value_at_risk` 施加生存成本。位置域
`peak_path_collision_risk` 与速度空间 `velocity_obstacle_risk` 取较大值后形成完整局部窗诊断；候选动作
预测窗内的子集再合并为条件生命成本输入，不重复计分。提交期子集仍以 `expected_health_loss` 保留，供
短期执行诊断和对局延续价值的风险换算，不再作为独立字段重复计分。弹道与队友 VO 使用连续 TTC 风险；
尚未发生的冲撞使用目标分布和解析到达时间。提交期概率风险与预测窗后段的生命损失、环境暴露分别进入
公共结果账本；只有提交期内确定且存在替代动作的死亡构成
[决策流程](#决策流程)第 8 步的执行资格。该边界只阻止已经不可撤销的终止转移，不指定逃离、接敌、
拾取或巡航方向。

环境暴露变化率和两类碰撞证据只保留在诊断账本中。敌人轨迹的位置不确定半径
只扩大邻近压力，不扩大 VO 的实体碰撞圆；伤害碰撞几何始终使用由玩家、敌人和投射物的标准碰撞形状
转换成的接触包围圆。规划层不推断、修补或替换这些必需字段，避免把精灵留白或“可能位于某处”误写成
“TTC 为零”。

友方作用区进入公共效用账本。炮塔和战斗宠物只有在
预测敌人进入其作用范围且仍对玩家形成近身压力时才产生减压价值；猫炮还要求玩家进入其可见启用范围。
地雷按一次性机会计分：原版踏板同时接受玩家与敌人，因此两者的预测路径都可消耗储备；只有当前可见
敌人进入爆炸覆盖时才兑现伤害价值，离开视野的记忆轨迹只形成环境压力。治疗覆盖随缺失生命提高权重。
水母盾只在预测会先于玩家截获威胁弹道时计分。
原版玩家和敌人的碰撞层不与构筑物碰撞；构筑物不参与实体掩体计算。

### 武器结果预测

`WeaponOutcomeForecastModel` 读取玩家自身武器的 `timing`、`delivery`、`impact` 和 `rules`，估计动作预测窗内
自动攻击对候选结果的期望修正。当前可见目标的中心距离按原版精确锁定边界准入，再按原版最近目标规则
分配主目标；目标外观半径只用于命中路径交会，不能增加锁定可用性。较远目标只有在所有更近目标不可用时
才获得主目标。锁定资格只决定能否开始攻击；共享的武器路径接触模型再以最大传播距离、走廊宽度和目标
外观半径计算实际主路径接触份额。导航完成价值和局部伤害、命中及命中后规则共用该份额，因此原版近战
额外锁定余量不会被误写成可命中距离。结果预测沿候选路径的起点、中点
与终点积分，因而接近目标只从实际形成攻击窗口之后产生输出，不把终点覆盖预付给整段动作。主目标的期望
分布确定攻击方向；直接贯穿只累计几何上落在路径角覆盖、走廊宽度和最大距离内的其他目标，弹射与命中后
投送再按覆盖目标质量、投送容量与伤害保留率折成期望乘数。主目标、直接路径次要目标和重定向目标都按
目标声明的完成机制归属命中容量，因此落在树木上的次要路径不会被记入敌人命中或敌人伤害。模型不构造
逐发、逐弹体、逐碰撞或逐事件传播图。

每个保留动作直接评价自身路径，避免空间插值抹平最近目标的 Voronoi 边界；这使细微位移造成的树木与敌人
目标归属变化能够进入效用账本。同一物理帧内仍复用目标运动预测与按移动状态投影的武器模型。每个路径
采样只排序一次最近目标；锁定范围与直接路径几何相同的武器共享覆盖和贯穿交会，再分别应用各自时序、
伤害、暴击、生命偷取与规则容量。完全可用的近目标会使后续目标的主目标选择权重归零；这些目标不再
展开直接路径交会，因为它们对期望值的贡献严格为零。其余目标仍使用相同的密集目标语义。

知识编译器把玩家自身当前可感知的剩余冷却与已显现攻击相位合成为下一次攻击就绪时间：原版在攻击动画
期间冻结冷却，因此进行中的攻击还要计入由稳定动画机制和当前相位得到的剩余时长。相位起点按观察物理帧
记录，误差不超过一个观察周期；两项当前事实都不由长期均值替代。首次机会之后才使用含额外长装填的长期
期望周期，不读取下一次尚未揭示的随机冷却，也不展开逐发状态机。因此接近锁定边界的价值会随当前节奏
自然变化，而不是由固定接战距离或开火策略触发。材料重置冷却等事件只有在统一规则投影能改变同一时序
状态时才计入，不另设内容特判。

每个路径采样先产生统一目标命中容量，再按目标的 `weapon_response` 解释完成机制。敌人完成等价数取
相应命中容量、伤害相对剩余生命可支持的完成量，以及覆盖目标质量三者的最小值；树木同时按伤害相对
剩余生命与玩家命中相对剩余命中上限计算完成份额，并采用先完成的一条路径；一击树效果把命中路径直接
变为一次。随后
`WeaponOutcomeConservationModel` 对所有武器和路径采样的累计结果统一守恒：敌人完成等价数不超过累计
敌人命中数和可见敌人数，敌人伤害不超过敌人总剩余生命，树木价值不超过树木总收获价值。奖励变化、
存活负担解除、死亡后果和击杀权重按同一个完成等价数同步缩放，不能分别消费同一批可见敌人。

### 计算预算与搜索工作分配

计算预算以实测物理回调峰值和规划成本为输入。`PhysicsFrameBudgetMonitor` 读取
`Performance.TIME_PHYSICS_PROCESS`；该字段的单位是单个物理帧耗时，Godot 3 在报告窗口内累计最大回调
耗时后发布监视值。控制层在同一 `idle frame` 内只推进一次估计，不按回调数归一；监视器以 `0.5 s`
时间常数平滑已发布峰值，预算直接使用该估计，不另加偏差项。物理帧容量由
`Engine.iterations_per_second` 派生。字段单位见
[Godot 3.5 Performance 文档](https://docs.godotengine.org/en/3.5/classes/class_performance.html#enum-performance-monitor)，
报告窗口的实现见
[Godot 3.x 主循环](https://github.com/godotengine/godot/blob/6ac964295fe9ed4b4e5d14ea4f732223a00a0ac6/main/main.cpp#L2337-L2542)：

```text
单个规划器的规划耗时预算
= min(控制窗长度, max(0, 物理帧容量 - 物理回调峰值 EMA) × 控制窗物理帧数)
  / 调度规划器数
```

`MovementPlanner` 用 `OS.get_ticks_usec()` 测量从投射物可达性过滤到动作选择完成的主要规划路径。
`PlanningComputeBudgetPolicy` 把控制窗内聚合帧余量转换成单调时钟截止。存在有效帧样本且预算为正时，它将近期
规划耗时占预算的比例平方并截断为连续预算压力；尚无帧样本时，或预算为正但尚无规划耗时估计时，压力
保持为零，不从未知状态推断过载；实测预算为零时，压力饱和。它只负责时间准入：额外导航评价和局部
角度细分仅在预计单项耗时仍容纳于统一最终截止时启动。每个保留候选仍执行相同的动作路径武器、碰撞和
事件预测。计算压力不会切换结果语义，也不会删除几何基线动作。

动作角向覆盖由玩家碰撞半径和一个提交期的移动距离派生，并完整保留为局部均匀基线。近似战略导航的
均匀格点随预算压力在四至八个方向间收缩；机会聚合方向与后续角区间细分都属于预算内搜索，只有经过
完整轨迹评价后才可能成为胜出导航方向。`PlanningSearchWorkAllocator` 以此前规划耗时对当前控制窗余量
的连续压力计算细分保真度：`q = q_min ^ budget_pressure`；导航额外评价额度与移动角区间精炼额度从该
细分保真度派生。整数化只发生在离散工作额度和导航方向数边界。

时间采样由碰撞直径、控制期与相关曲线弹最大角频率推导，不随可选搜索额度降低。动作搜索从当轮均匀动作
格点与胜出导航方向形成可执行基线，再在优胜动作的相邻角区间递归插入
中点。导航与近场的额外工作同时受曲线额度和统一最终截止约束，避免任一前置阶段通过内部循环耗尽后续
计算时间。

`ProjectileReachabilityFilter` 在重复战术扫掠之前，用导航时域内玩家最大位移、可见投射物当前速度、
已观察加速度和已解析曲线速度的保守积分上界判断规划域可达性。不能影响局部可达域的投射物仍保留在
原始观察和遥测中，但不再提高局部时间采样数，也不参与每个动作的重复碰撞计算。敌人尚无适用于全部
规划消费者的统一最大机动能力契约，因此不会从规划观察中全局延后；武器结果预测只消费当前可见敌人的
短时运动估计，不把不可见目标或运动不确定域扩写成火力收益。

`projectile_filter` 公开过滤结果：`included_projectile_count` 与 `deferred_projectile_count` 分别记录进入
重复规划计算和被延后的投射物数；`horizon_seconds` 是判定使用的有效导航时域；`mode` 记录当前保守距离
判据。过滤后的观察只在规划包内部传递，不替换采样中的原始公共观察。

敌人运动预测由规划器注入一个物理帧作用域的共享实例，按“轨迹、预测时刻、候选玩家位移”复用完整
位置响应结果；语义模型不再各自持有重复的可变积分缓存。每个不同候选仍单独计算玩家位移造成的位置响应
反事实。武器结果预测按候选动作直接评价路径，不跨帧保留地图或目标状态。
`model.derived.enemy_position_response_cache` 记录目标位置响应预测的缓存命中数、未命中数与复用比例，
供性能复盘确认共享是否生效；这些诊断不参与预算或动作选择。

`compute_budget` 公开本轮分配和反馈状态：

| 字段 | 含义 |
| --- | --- |
| `budget_model`、`budget_pressure`、`has_deadline` | 当前使用的控制窗帧余量预算模型、`[0, 1]` 预算压力，以及本轮是否有可用最终截止；压力通常由预测预算利用率平方得到，无帧样本或正预算下尚无规划成本估计时为 `0`，实测预算为零时为 `1` |
| `planning_started_usec`、`planning_deadline_usec` | 规划起点与本轮计算的最终截止 |
| `planning_deadline_overrun_usec` | 实际结束时超过最终截止的微秒数；无帧样本时为 `null` |
| `estimated_work_unit_duration_usec` | `navigation_evaluation` 与 `movement_refinement` 单次额外工作耗时的 EMA |
| `physics_frame_capacity_usec` | 由物理帧率派生的单帧容量 |
| `physics_process_peak_usec_ema` | Godot 报告窗口内最大物理回调耗时的指数移动平均 |
| `planning_window_usec`、`planning_window_physics_frames` | 一次重规划周期的墙钟长度和包含的物理帧数；单帧余量在这个后台计算窗口内聚合后才形成规划预算 |
| `has_frame_time_sample`、`scheduled_planner_count` | 帧耗时样本是否有效，以及共享余量的规划器数量 |
| `planning_duration_budget_usec` | 分配给单个规划器的本轮耗时预算 |
| `planning_duration_usec`、`planning_duration_usec_ema` | 本轮实测规划耗时及其指数移动平均 |
| `planning_turnaround_usec` | 从后台规划开始到主线程接收并准备应用结果的总周转时间，包含计算、线程调度和轮询等待 |
| `predicted_planning_budget_utilization` | 分配时已知的规划耗时 EMA 与本轮预算之比；用于形成预算压力 |
| `planning_duration_budget_utilization` | 本轮实测耗时与耗时预算之比；大于 `1` 表示超出预算 |

`search_work_allocation` 记录本轮搜索工作分配：`allocation_model`、`budget_pressure`、受压力影响的
`refinement_fidelity` 及其下限；`navigation_baseline_direction_count`、
`navigation_extra_evaluation_limit` 与 `movement_refinement_limit` 记录本轮额度。
局部几何方向基线另由 `model.derived.geometry_direction_count` 记录，不混入预算分配。该记录只解释搜索
计算，不改变碰撞时间采样，也不改变敌人、材料、消耗品、构筑物或风险本身的价值。预算压力只能削减
导航额外评价、动作角区间细分，并把近似战略价值场的均匀扫描从八向收缩至四向；不能删除由碰撞几何
派生的均匀动作格点。导航价值在保留样本间作环形插值，因此局部动作仍得到连续的延续价值证据。

动作基线在均匀方向之外只加入已经通过完整轨迹评价胜出的导航方向，并单独加入零移动输入。单步动作空间
使用确定性自适应角区间，不需要模拟退火；若以后允许多个自由动作段，组合数会指数增长，届时再考虑束
搜索或交叉熵方法。

后台规划不在物理回调中执行；其 CPU 争用对主线程的影响会在后续报告的物理回调峰值中体现。单项耗时
EMA 只能阻止启动预计无法在截止前完成的额外工作，不能中断已经开始的单项计算；基线工作、首次成本
估计、同帧突发负载和监视值更新延迟仍可能造成超预算。预算为零或尚无帧样本时都不启动受截止控制的
额外工作；两者都保留完整几何动作基线，后者不凭未知状态降低细分保真度。

## 算法依据与适用边界

- Khatib 的人工势场提供了实时局部避障的运行成本思想，但普通吸引/排斥势场存在局部极小值问题，因此
  本实现不直接沿暴露梯度控制。
- Fiorini–Shiller 的 Velocity Obstacle 与原版“输入直接决定平移速度”的一阶动力学匹配，用于动态
  圆盘交会；玩家可主动承伤，所以实现采用 TTC 连续松弛而不是硬禁用所有碰撞锥内速度。
- 滚动时域控制负责组合短期运行成本、战斗收益和导航轨迹价值；离散动作搜索是受限预算的 MPC
  近似，不提供机器人控制意义上的稳定性或安全证明。
- 可行域与控制余量的观点用于表达下一控制期的角向机动余量：可达敌人圆盘与已知地图边界转换为遮蔽
  角区间并取并集。边界不是硬禁区，聚团、包围和边界重叠的差异由剩余可用方向产生，而不是由独立
  边缘惩罚或角落倍率产生。
- POMDP 的信念状态观点用于区分“已经观察到的世界”与“对当前世界的置信估计”。地图探索不再编码方向，
  而把候选视点带来的新观察和对陈旧覆盖的再观察作为后续决策价值；当前即时生存缓冲形成局部暴露单价，
  有限时域内可兑现的补充流形成补给库存影子价格。概率终止风险和预测窗后段风险仍与其他动作结果在
  同一效用账本交换；可避免的确定提交期死亡由执行资格单独处理。
- 动态随机背包的容量影子价格用于解释“现在消耗一单位可补充库存会放弃多少后续选择”；随机可达性则
  启发即时可生存性与期望性能分离。当前实现只是适合实时预算的确定性等价近似，不声称求解完整动态规划
  或提供概率安全保证。
