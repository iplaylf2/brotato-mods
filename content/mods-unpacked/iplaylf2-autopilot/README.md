# Autopilot

Autopilot 是一个实验性 Brotato mod。它在玩家权限边界内评估环境暴露、碰撞风险、资源和交战机会，
再通过滚动规划选择战斗移动方向。唯一的控制输出是 `MovementBehavior.get_movement()` 返回的移动向量；
瞄准、攻击、速度、碰撞、击退、动画和移动机制仍由原版系统负责。

## 目标环境与验证状态

- 目标环境为 Brotato `1.1.15.4` 和 Godot Mod Loader `6.3.0`；以 `manifest.json` 中的声明为准。
- 当前源码已通过可移植静态检查、Godot 3.7.dev 脚本编译检查、模型语义契约检查，以及真实战术/战略
  规划器的独立后台周期与值交接契约检查。
- 当前规划与模型变更尚未在目标游戏构建中完成回归测试；多人模式及不同设备上的性能也尚未验证，因此当前
  版本仍是开发版。这些工具检查不评估游戏内稳定性、行为质量或模型参数校准。

## 安装与启用

将 Autopilot 发行 ZIP 直接放入 Brotato 安装目录的 `mods/`，无需解压。Autopilot 依赖
[Mod Options](https://steamcommunity.com/sharedfiles/filedetails/?id=2944608034)；安装并启用两者后，在游戏中打开
`设置 → Mods → Autopilot`：

- **Enable Autopilot** 允许 Autopilot 控制战斗移动；
- **Record Battle Samples** 写入本地战斗样本。它与控制开关相互独立；只开启采样时，文件记录人工移动，
  可作为复盘和校准参考。

两个开关均默认关闭。

设置会立即作用于当前战斗并保存到后续战斗。关闭后，Autopilot 会停止移动并恢复玩家原有的
`MovementBehavior`。采样设置独立生效；具体路径、采样频率和记录结构见
[诊断与采样](#诊断与采样)。

## 公平边界

- 公平性按信息语义和披露时点判断，不按字段是否属于内部实现或能否精确读取判断；已经呈现的当前状态
  可以直接读取原版权威值，不必通过图像识别或重复估算还原。
- 外部战场信息只通过玩家可感知的渠道进入观察；普通敌人离开视野后只依据先前观察继续估计，原版持续
  血条公开的生命与存活以及首次看见的必掉产物按权限契约单独处理。
- 玩家通过正常游玩可以掌握的敌人、树木、投射物和波次机制可以作为预置知识，不要求每局重新学习。
- 确定性结算使用当前确认值；含随机分布的机制使用数学期望，不读取尚未揭示的随机结果或即时意图。
- 玩家自身状态可以参与规划，但唯一控制输出始终是 `MovementBehavior.get_movement()` 的返回值。
- 只读武器结果估计只用于比较移动动作，不会调用或修改瞄准、攻击、目标、冷却、伤害和实体状态。

完整规则见 [玩家权限边界](docs/fair-play.md)。

## 工作方式

Autopilot 用当前可见信息、玩家自身状态、稳定机制知识和先前合法观察建立局内世界模型。多速率规划器让
战术线程每三个物理 tick 重新比较零输入与各个移动方向，让战略线程每十二个物理 tick 刷新长时域导航
价值场。战术规划只执行一个短控制期，并消费带来源帧和期限的最新完整战略指导；战略计算过慢或指导过期
时，局部避险与动作评价仍能独立运行。后台计算期间上一输入继续生效，因此候选从按已发生排队时间和近期
计算成本外推的预计生效状态开始比较。规划线程启动失败时不接管移动；运行中失效时立即交还控制。线程
所有权、数据隔离和失败处理见
[模块边界与责任](docs/module-boundaries.md#运行时边界与依赖)。

局部动作始终保留由玩家几何派生的均匀输入和零输入。导航在较长时域内沿候选轨迹比较资源、交战、信息
和环境暴露相对同刻零输入反事实的变化。机会位置只提供预算内搜索提案；只有经过完整轨迹评价后胜出的
方向才能补入动作候选。敌人、材料、消耗品、树木和友方支援共享同一效用账本，不触发预设行为模式。

碰撞证据按未来运动的可知性分工：已有受支持轨迹的实体只由连续路径扫掠判定交会；尚无受支持轨迹的
未来实现才进入未解析风险分布。邻近压力描述机动环境，不等同于命中，也不会把所有靠近威胁的路径一并
放大为碰撞风险。

每个保留动作都在同一近端动作窗内比较环境、武器和事件结果；几何接触单独前视到默认局部窗，避免遗漏
刚好落在近端窗外的来袭。位置接触按预测时刻进入生命状态演化，
连续亚致命接触的结果由当前生命、当前无敌剩余时间、闪避、命中保护、护甲和受伤后无敌时间共同产生，
不依赖固定的“一击或两击致死”判断。计算压力可以减少战略导航的均匀方向数和额外搜索工作，但不改变
由碰撞几何派生的局部动作基线、时间采样或保留候选的结果语义。选择器只排除下一次重规划前确定且可避免
的死亡；其余承伤风险会随当前持有材料、道具和武器的替代价值连续计价，并与交战、恢复和资源收益共同
决定方向。
具体观察字段、价值模型、候选资格和预算契约见
[架构文档](docs/architecture.md)。

## 诊断与采样

任一开关启用并进入战斗后，都可以读取某位玩家的最新观察；只有 Autopilot 正在控制时才有当前计划：

```gdscript
var observation: Dictionary = main.autopilot_observation_service.get_observation(player_index)
var plan := {}
if is_instance_valid(main.autopilot_controller):
	plan = main.autopilot_controller.get_current_plan(player_index)
```

计划包含所选动作、移动方向、结果字段、字段级与目标级效用账本、价值上下文、导航意图、战术计算预算与
搜索工作分配、所用战略指导的来源和独立计算摘要、动作生效时刻投影、投射物过滤诊断及高分动作摘要，
供游戏内诊断与模型校准。

开启采样后，bot 控制期间会为每位玩家记录第一次决策，此后每 10 次战术重规划记录一次，并额外记录规划失败；
人工控制期间则约每秒记录一次观察与实际移动输入。当前文件路径可由
`main.get_current_battle_sample_path()` 读取。样本写入
`user://logs/mods/iplaylf2-autopilot/<run-id>/`：一次完整对局共用一个目录，目录内文件名以波次和
`human`/`bot` 控制来源区分，每个控制分段只写一个文件。Windows 上 `user://` 对应
`%APPDATA%/Brotato/`，因此日志根目录通常是
`%APPDATA%/Brotato/logs/mods/iplaylf2-autopilot/`；Mod Loader 日志也会打印
当前文件的 `user://` 路径和绝对路径。游戏暂停时观察、规划和采样停止；恢复后继续写入
同一分段文件。样本分批刷新，正常关闭时会写完队列；异常退出时，尾部样本仍可能缺失。

采样不包含两条样本之间的全部决策，不能作为逐帧回放；字段约定、参数证据等级和正确复盘方法见
[战斗采样与模型校准](docs/model-calibration.md)。
