# Autopilot

Autopilot 是一个实验性 Brotato mod。它在玩家权限边界内评估环境暴露、碰撞风险、资源和交战机会，
再通过滚动规划选择战斗移动方向。唯一的控制输出是 `MovementBehavior.get_movement()` 返回的移动向量；
瞄准、攻击、速度、碰撞、击退、动画和移动机制仍由原版系统负责。

## 目标环境与验证状态

- 目标环境为 Brotato `1.1.15.4` 和 Godot Mod Loader `6.3.0`；以 `manifest.json` 中的声明为准。
- 当前源码已通过可移植静态检查、Godot 3.7.dev 脚本编译检查、模型语义契约检查，以及真实
  `MovementPlanner` 首次和后续后台规划周期的执行契约检查。
- 当前规划与模型变更尚未在目标游戏构建中完成回归测试；多人模式及不同设备上的性能也尚未验证，因此当前
  版本仍是开发版。这些工具检查不评估游戏内稳定性、行为质量或模型参数校准。

## 安装与启用

Autopilot 依赖 [Mod Options](https://steamcommunity.com/sharedfiles/filedetails/?id=2944608034)，并且默认
关闭。安装依赖后，在游戏中打开 `设置 → Mods → Autopilot`，启用 **Enable Autopilot**。

设置会立即作用于当前战斗并保存到后续战斗。关闭后，Autopilot 会停止移动并恢复玩家原有的
`MovementBehavior`。启用且进入战斗后，Autopilot 还会在本地写入决策采样文件；具体路径、采样频率和
分片策略见[诊断与采样](#诊断与采样)。

## 公平边界

- 外部战场信息只通过玩家可感知的渠道进入观察；普通敌人离开视野后只依据先前观察继续估计，原版持续
  血条公开的生命与存活以及首次看见的必掉产物按权限契约单独处理。
- 玩家通过正常游玩可以掌握的敌人、树木、投射物和波次机制可以作为预置知识，不要求每局重新学习。
- 确定性结算使用当前确认值；含随机分布的机制使用数学期望，不读取尚未揭示的随机结果或即时意图。
- 玩家自身状态可以参与规划，但唯一控制输出始终是 `MovementBehavior.get_movement()` 的返回值。
- 只读武器结果估计只用于比较移动动作，不会调用或修改瞄准、攻击、目标、冷却、伤害和实体状态。

完整规则见 [玩家权限边界](docs/fair-play.md)。

## 工作方式

Autopilot 用当前可见信息、玩家自身状态、稳定机制知识和先前合法观察建立局内世界模型。规划器反复比较
零输入与各个移动方向，每轮只提交一个短控制期的移动输入，再用新观察重新求解。规划在单一后台线程中
运行；线程不可用时不接管或立即交还移动控制。线程所有权、数据隔离和失败处理见
[模块边界与责任](docs/module-boundaries.md#运行时边界与依赖)。

局部动作始终保留由玩家几何派生的均匀输入和零输入。导航在较长时域内沿候选轨迹比较资源、交战、信息
和环境暴露相对同刻零输入反事实的变化。机会位置只提供预算内搜索提案；只有经过完整轨迹评价后胜出的
方向才能补入动作候选。敌人、材料、消耗品、树木和友方支援共享同一效用账本，不触发预设行为模式。

每个保留动作都接受相同口径的碰撞、武器、事件和生命结果预测。计算压力只收缩额外搜索覆盖，不改变
基础动作覆盖、时间采样或保留候选的结果语义。选择器只排除下一次重规划前确定且可避免的死亡；其余
承伤风险会随当前持有材料、道具和武器的替代价值连续计价，并与交战、恢复和资源收益共同决定方向。
具体观察字段、价值模型、候选资格和预算契约见
[架构文档](docs/architecture.md)。

## 诊断与采样

启用并进入战斗后，可以读取某位玩家的最新观察和计划：

```gdscript
var observation: Dictionary = main.autopilot_observation_service.get_observation(player_index)
var plan: Dictionary = main.autopilot_controller.get_current_plan(player_index)
```

计划包含所选动作、移动方向、结果字段、字段级与目标级效用账本、价值上下文、导航意图、计算预算、
搜索工作分配、投射物过滤诊断和高分动作摘要，供游戏内诊断与模型校准。

控制器会为每位玩家记录第一次决策，此后每 10 次重规划记录一次，并额外记录规划失败；按名义
`0.1` 秒控制期计算，常规采样间隔约为 `1` 秒，实际间隔可能随物理帧调度和规划周转延长。样本写入
`user://logs/mods/iplaylf2-autopilot/` 下的 JSON Lines 文件，单个文件达到
32 MiB 后自动分片。Windows 上 `user://` 对应 `%APPDATA%/Brotato/`，因此完整目录通常是
`%APPDATA%/Brotato/logs/mods/iplaylf2-autopilot/`；Mod Loader 日志也会打印
当前文件的 `user://` 路径和绝对路径。游戏暂停时观察与规划停止，不会新增决策样本；恢复后继续写入
同一会话文件。每位玩家的首条决策样本立即刷新到磁盘，后续样本分批刷新；异常退出时，尾部样本仍可能
缺失。

采样不包含两条样本之间的全部决策，不能作为逐帧回放；字段约定、参数证据等级和正确复盘方法见
[决策采样与模型校准](docs/model-calibration.md)。
